# Dodo Audit Service — инструкции для работы в этом репозитории

Проект: Dodo Audit Service — система выездных проверок пиццерий. Точка входа — `README.md`, порядок чтения там же.

## Прежде чем писать код

Прочитать `docs/02-domain.md` (методика) и `docs/03-recording-rules.md` (правила формулировок). Оба короткие. Без них код будет работать, а отчёты будут неверными.

## Жёсткие требования

**Оценку не считать заново.** Проценты, буква, разбивка по зонам, сроки — только через `engine/audit.py score`. Ставки вычетов и пороги букв живут в `data/scoring.json`, в коде их не дублировать.

**Сущности связывать кодами, никогда формулировками.** Формулировки переводятся и правятся, коды нет.

**Язык — параметр, никогда не константа.** Три отдельных поля: язык интерфейса, язык речи аудитора, язык отчёта.

**Модель предлагает, фиксирует человек.** Ни одна запись не попадает в отчёт без подтверждения аудитора.

## Что не решать самостоятельно

Выбор платформ и внешних сервисов (Supabase, Cloudflare, хостинг, очереди) — предлагать варианты с обоснованием, решение за Garva. Имеющиеся ресурсы: штатный сервер, ноутбук с Postgres.

## Проверка, что ничего не сломалось

```bash
cd examples/belgrade-1 && python3 ../../engine/audit.py score   # 97.5%, A, 5×D1
cd ../belgrade-2       && python3 ../../engine/audit.py score   # 97.0%, A, 6×D1
```

Любое изменение движка или данных, после которого эти цифры разошлись, — регрессия.

## Стиль работы

Считать, а не прикидывать. На этом проекте каждая оценка «по ощущению» — трудоёмкость, стоимость, скорость, точность — оказывалась неверной в разы. Список конкретных промахов: `docs/05-calibration.md`.

## Дизайн-система живёт не здесь

Визуальный язык продукта — в репозитории **GarroV/forma**, папка `dodo/`:
ядро одно на три продукта линейки (MAXIMUS — P&L, DECIMUS — этот,
MERIDIUS — чек-листы), слой этого продукта лежит там же
(`dodo/decimus/domain.css`).

Здесь лежат только **копии**: `design/dodo-ds.css` (ядро) и
`design/domain.css` (классы нарушений, буквы оценки, предписания).

**Копии не правят.** Первая строка каждого файла несёт штамп с контрольной
суммой содержимого; правка на месте делает прогон красным. Причина простая:
правка, сделанная здесь, не достанется двум другим продуктам, и язык снова
разъедется на три — ровно так он и разошёлся до сборки 17.09.2026.

Схема работы:

```
нужна правка → ~/Documents/projects/forma
                 правишь dodo/core/dodo-ds.css (общее для троих)
                 или dodo/decimus/domain.css (только наше)
                 python tools/guard.py stamp && коммит
                 python tools/spread.py --apply   → файлы легли сюда
               → здесь остаётся закоммитить и проверить глазами
```

Не хватает токена или компонента: нужен **одному** продукту — заводится
в `dodo/decimus/domain.css`; нужен **двум и больше** — в ядре. Заведёшь
у себя — получишь четвёртую копию языка.

Куда смотреть: [`dodo/docs/consumers.md`](https://github.com/GarroV/forma/blob/main/dodo/docs/consumers.md)
(пути и код проверки), [`layers.md`](https://github.com/GarroV/forma/blob/main/dodo/docs/layers.md)
(что в каком слое), [`decisions.md`](https://github.com/GarroV/forma/blob/main/dodo/docs/decisions.md)
(почему так). Приёмка — задача #273.
