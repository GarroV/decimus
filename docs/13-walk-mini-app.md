# Мини-апп обхода в Telegram

Рабочий экран аудитора на точке (#418, D312). Отвечает на вопрос **«что мне
ещё посмотреть и записать в этой пиццерии?»** и позволяет записать находку
прямо здесь: фото, пункт, класс, что видно, рекомендацию партнёру. Чат с ботом
остаётся рабочим путём наравне с мини-аппом: обе дороги пишут в одну проверку.

Статус: прототип, 07.10.2026. Поднят на стенде разработки в режиме просмотра
без бота. На прод не раскатывался.

## Что видит аудитор

Вход — кнопка **«Обход точки»** под сообщениями бота «Проверка начата» и
«Продолжаем проверку». Начинается и завершается проверка в чате: мастер старта
(точка, вид, языки) и сборка отчёта остаются у бота.

Экран один, сверху вниз:

1. **Точка и прогресс.** «Осмотрено зон: 4 из 10» и полоска из десяти делений.
   Процент оценки не показывается до конца проверки (D072).
2. **Осталось осмотреть.** Неосмотренные зоны кнопками. Зона, где остались
   неперепроверенные прошлые замечания, подсвечена.
3. **В прошлый раз.** Дата, число замечаний, «повтор стоит вдвое» (D191) и
   «Ещё не перепроверено: N».
4. **Зоны** в порядке методики. Раскрытая зона показывает:
   - **Было в прошлый раз** — с кнопками «Исправлено» (личная пометка) и
     «Не исправлено» (открывает форму с этим пунктом, зоной, классом и
     предложенным повтором). Если пункт уже записан снова — метка «Записано
     снова»;
   - **Записано сейчас** — карточки записей: первое фото, класс, что видно,
     рекомендация, пометка «повтор ×2». Нажатие открывает запись на правку;
   - кнопки **«+ Нарушение»** и **«+ Замер»** (замер — только если в методике
     есть замеры для этой зоны);
   - **«Зона осмотрена»** — только у чистой зоны: зона с записью
     засчитывается сама.
5. **Сведения о визите** — информационная часть отчёта (INF01, INF03–INF08):
   состав смены, предписание и закрытие точки (да/нет), созвон и срок плана
   (даты), **«Что улучшить» — общая рекомендация к визиту**, отзыв о тестовом
   заказе. Что заполнено здесь, бот в конце не спрашивает.
6. Внизу всегда видна кнопка **«Записать нарушение»** — для находки, зону
   которой аудитор выберет в форме.

### Форма записи

Одна форма на новое нарушение, замер и правку. Шагов-экранов нет: всё видно
сразу, в том порядке, в каком аудитор действует.

| Блок | Что делает | Правило |
|---|---|---|
| **Фото** | «Снять» (задняя камера) и «Из галереи» (несколько сразу). Кадр сжимается на телефоне до 1600 px и уходит на сервер сразу, не дожидаясь «Сохранить». Неудача — «Не загрузилось — повторить» на самом кадре | Без фото «Сохранить» не нажимается (D078). Несколько ракурсов — одна запись |
| **Зона** | Подставлена из зоны, откуда открыта форма; меняется нажатием | Зона вне списка пункта принимается с пометкой (D206) |
| **Что нарушено** | Поиск словами по пунктам методики («пол», «дата», «перчатки»). Сначала пункты этой зоны, пункты прошлой проверки — первыми с меткой «было в прошлый раз». «Все пункты» снимает фильтр по зоне | Служебные пункты не предлагаются (правило 8) |
| **Класс** | Только допустимые для пункта. Один допустимый ставится сам | Границы классов — из критериев (правило 9) |
| **Что видно** | Свободный текст. Пусто — берётся формулировка пункта без служебного префикса (Q045) | Формулировка — факт, а не реплика (правило 13) |
| **Рекомендация партнёру** | Скрыта за «+ Добавить рекомендацию» | Печатается в отчёте под записью строкой «Рекомендация» |
| **Повтор ×2** | Появляется, только если в прошлый раз в этой зоне был этот же пункт и класс D1/D2 | Ставит человек (D191). Подсказка: «исправили и снова сломалось — не повтор» |

## Сценарии

| Ситуация | Что происходит |
|---|---|
| Нашёл нарушение | Зона → «+ Нарушение» → Снять → пункт → класс → «Сохранить». Запись появляется в зоне, зона засчитана |
| Несколько ракурсов одного нарушения | Несколько фото в одной форме — одна запись, один вычет |
| Тот же пункт в этой зоне уже записан | Форма говорит «Это уже записано (№N)», класс и текст скрываются, кнопка — «Добавить фото к записи». Пара «пункт + зона» уникальна |
| Тот же пункт в другой зоне | Отдельная запись, отдельный вычет — как в методике |
| Прошлое замечание не исправлено | «Не исправлено» в блоке «Было в прошлый раз» → форма с пунктом, зоной, классом и отмеченным повтором; осталось снять фото |
| Прошлое замечание исправлено | «Исправлено» — личная пометка, счётчик «Ещё не перепроверено» уменьшается |
| Замер (температура, настройки печи, фото продукта) | «+ Замер» → пункты D0 → фото → показание («−18 °C»). На оценку не влияет, в отчёт идёт приложением |
| Ошибся пунктом, классом, зоной, текстом | Нажать карточку записи → поправить → «Сохранить» |
| Лишнее фото | В записи — ✕ на кадре. Последнее фото снять нельзя: сначала добавить другое |
| Запись не нужна | Карточка → «Удалить запись» → «Да, удалить» |
| Нужна рекомендация к пункту | В форме «+ Добавить рекомендацию» |
| Нужна общая рекомендация к визиту | «Сведения о визите» → «Что улучшить» |
| Зона чистая | «Зона осмотрена» |
| Пропала связь при загрузке фото | Кадр помечен «Не загрузилось — повторить», «Сохранить» ждёт. Черновик формы живёт на телефоне и возвращается при следующем открытии формы |
| Случайно закрыл форму | С несохранённым — вопрос «Закрыть без сохранения?»; в Telegram ещё и подтверждение закрытия окна |
| Записал что-то в чате, вернулся в мини-апп | Данные обновляются при возврате в окно |
| Отчёт уже сдан | Плашка «Отчёт сдан — записи больше не меняются», кнопок записи нет, сервер отказывает 409 (D080) |
| Проверка не начата | «Начните проверку в чате с ботом» |
| Движок отказал (класс не разрешён и т. п.) | Его слова показываются над кнопкой «Сохранить», форма остаётся открытой |

## Что откуда берётся и куда пишется

| Что на экране | Источник / куда пишет |
|---|---|
| Зоны, пункты, классы | Методика того издания, по которому идёт проверка (`list_zones`, `list_items` с `chat_id`) |
| Записи | Состояние бота `STATE_DIR/chat_<id>/inspection.json`. Пишется функциями домена `add_finding`, `edit_finding`, `drop_finding`, `attach_photo`, `detach_photo` — теми же, что у бота |
| Кадры мини-аппа | Файлом в `STATE_DIR/uploads/`, в записи — ссылкой `walk:<отпечаток>` (`src/domain/uploads.py`). Бот читает её той же дверью, что и кадры Telegram (`bot/photos.fetch_bytes`): сборка отчёта, выгрузка в хранилище и пересылка работают без изменений |
| Кадры из чата | Идентификатор Telegram. Мини-апп их не показывает (у веба нет скачивания из Telegram) — на месте превью «фото из чата» |
| Рекомендация к записи | Поле записи `comment`. Бот его не заполнял; в отчёте подпись «Рекомендация» / «Recommendation» |
| Сведения о визите | `set_info`. Состав полей — `src/domain/info_fields.py`, один для бота и мини-аппа |
| Было в прошлый раз | `queries.previous_findings` — та же прошлая проверка, что у вопроса о повторе (D255) |
| «Зона осмотрена», «Исправлено» | Личные пометки в `CloudStorage` Telegram, вне Telegram — `localStorage`. На оценку не влияют |
| Сдана ли проверка | `domain.handed_over` — тот же признак в заметках бота, что у его запрета правки (`src/domain/handover.py`) |

Источник записи — `comment` (слова аудитора, D044): модель в мини-аппе не
участвует, формулировку пишет человек.

## Как устроено

| Часть | Где |
|---|---|
| Страница `/tg/walk`, данные `POST /tg/walk/data`, опознание | `src/web/walk.py` |
| Запись: `POST /tg/walk/photo`, `/photo/view`, `/finding`, `/info` | `src/web/walk_write.py` |
| Подпись `initData` | `src/web/walk_auth.py` — `safe_parse_webapp_init_data` из aiogram, срок 6 часов. В запросах записи — заголовок `X-Telegram-Init-Data` |
| Тексты (ru, en) | `src/web/texts_walk.py`. В скриптах строк нет |
| Экран | `templates/walk.html`; `static/walk-core.js` (общее), `walk-photo.js` (камера, сжатие, загрузка), `walk-sheet.js` (форма), `walk.js` (экран); стили `walk.css`, `walk-record.css` |
| Кнопка в боте | `keyboards.walk_keyboard`, `routers/start.py` |
| Заголовки | `security_headers.WALK_*`: рамка — только `*.telegram.org`, скрипты — свои и `telegram.org`, картинки — свои и `blob:` |
| Том состояния | Веб монтирует `state` **на запись** (`docker-compose.yml`). Пишут только адреса `/tg/walk/*`; одновременную запись с ботом разводит замок движка |

Действие записи → ответ — свежие данные экрана целиком: экран не собирает
состояние по кусочкам и не расходится с проверкой.

**Доступ.** Адреса открыты без учётки админки (`auth.OPEN_ENDPOINTS`).
Опознаёт подпись Telegram, читать и писать можно только проверку своего чата.
Человеку со снятой привязкой или отключённой учёткой — отказ (`walk.revoked`);
база молчит — 503, а не «пускаю вслепую». Кадр показывается, только если он
висит на записи или сведении своей проверки: отпечаток кадра — не пропуск к
чужой. Запись принимает подпись только заголовком: тело (кадр до 10 МБ) не
читается, пока не известно, чьё оно. Кадр должен разбираться как JPEG не
больше 50 Мп, а не только начинаться им; ссылка собирается в путь только из
шестнадцатеричных цифр. Текст с управляющими символами не принимается. Снятие
кадра делает движок одной командой под своим замком (`photo N --remove`), так
что одновременная правка с ботом ничего не теряет. Просмотр без подписи
(`WEB_WALK_PREVIEW_CHAT`) открывается только на вымышленный диапазон чатов
сидов: с D312 он пишет, и забытая переменная не откроет живую проверку.

Принятый риск (ревью 07.10.2026): человек, которого пускали только по списку
`ALLOWED_TELEGRAM_IDS` без привязки, после удаления из списка ещё видит и
правит свою последнюю проверку, пока её состояние лежит на диске. Полный
допуск бота учитывает `roster.json` блока `bot`, а веб блок `bot`
импортировать не может (`import-linter`). Ограничителя частоты пока нет (#529).

**До раскатки записи на прод** закрыть замечания ревью безопасности
07.10.2026 — они в приватном security advisory репозитория.

**Проверка защит порчей:** `.venv/bin/python tools/porcha_walk.py` ломает по
одной защите (сданная проверка, владелец кадра, кадр обязателен, снятый
доступ, ссылка-путь, повторный вопрос сведений, последний кадр, повтор у
замера) и требует, чтобы упал её тест.

## Настройка

| Переменная | Кто читает | Что делает |
|---|---|---|
| `BOT_WALK_URL` | бот | Адрес страницы, только `https://`. Пусто — кнопки нет |
| `TELEGRAM_BOT_TOKEN` | веб | Ключ для проверки подписи. Есть — мини-апп включён. Нет — адреса отвечают 404 |
| `WEB_WALK_PREVIEW_CHAT` | веб | **Только стенд:** открыть экран без подписи на этот чат — и читать, и писать. Вместе с токеном — отказ на старте |

## Стенд прототипа

Домашний сервер разработки, отдельный проект compose `decimus-walk`: сервисы
`db` и `web` из штатного `docker-compose.yml`, методика — синтетическая
`tests/methodology`, `WEB_WALK_PREVIEW_CHAT` на чат сида. Адрес стенда в
репозитории не записывается: он публичный, а стенд открыт без входа и на
запись.

Картину стенда собирает `tools/seed_walk_stand.py`: прошлая проверка точки
«Тестоград-1» с четырьмя замечаниями и идущая проверка, где одно замечание
повторилось. Повторный запуск возвращает стенд к исходному виду — и стирает
всё, что туда записали руками.
