# Мини-апп обхода в Telegram

Второй экран аудитора на точке (#418). Отвечает на один вопрос: **что мне
ещё посмотреть в этой пиццерии?** Фиксация нарушений остаётся в чате с ботом,
мини-апп ничего в проверку не пишет.

Статус: прототип, 07.10.2026. Поднят на стенде разработки в режиме просмотра
без бота. На прод не раскатывался.

## Что видит аудитор

Вход — кнопка **«Обход точки»** под сообщениями бота «Проверка начата» и
«Продолжаем проверку». Экран один, сверху вниз:

1. **Точка и прогресс.** «Осмотрено зон: 4 из 10» и полоска из десяти
   делений.
2. **Осталось осмотреть.** Названия неосмотренных зон кнопками. Нажатие
   раскрывает зону. Зона, где в прошлый раз были замечания, которые ещё не
   перепроверены, подсвечена.
3. **В прошлый раз.** Дата прошлой проверки, число замечаний и напоминание,
   что повтор стоит вдвое (D191). Ниже — «Ещё не перепроверено: N».
4. **Зоны** в порядке методики. В строке зоны видно, сколько записано сейчас
   и сколько прошлых замечаний осталось перепроверить. Раскрытая зона
   показывает:
   - **Было в прошлый раз** — формулировки прошлых записей. У каждой записи
     кнопка «Исправлено». Если тот же пункт в той же зоне уже записан сейчас,
     вместо кнопки стоит метка «Записано снова»;
   - **Записано сейчас** — записи этой проверки;
   - кнопку **«Зона осмотрена»**. Она нужна только чистой зоне: зона, где
     есть запись, засчитывается сама.

Новичку подсказка «Осмотрели зону — отметьте её…» видна до первой отметки.

## Что откуда берётся

| Что на экране | Источник |
|---|---|
| Зоны и их порядок | Методика того издания, по которому идёт проверка (`list_zones(chat_id=…)`) |
| Записано сейчас | Состояние бота `STATE_DIR/chat_<id>/inspection.json`, только чтение |
| Было в прошлый раз | `queries.previous_findings` — та же прошлая проверка, что у вопроса о повторе (`previous_inspection`, D255) |
| Текст прошлой записи | Формулировка той записи. Если её нет — вопрос методики без префикса классов |
| «Зона осмотрена», «Исправлено» | Личные пометки аудитора в `CloudStorage` Telegram, свой ключ у каждой проверки. Вне Telegram — `localStorage` |

Пометки на оценку не влияют, в отчёт и базу не попадают. Поэтому сервер
остаётся только читателем: веб монтирует состояние бота с `:ro`, как и
раньше. Бот их не видит. Напоминание «не отмечены зоны» при «Завершить»
появится, когда пометки переедут на сервер (см. «Что дальше»).

## Как устроено

| Часть | Где |
|---|---|
| Страница `/tg/walk` и данные `POST /tg/walk/data` | `src/web/walk.py` |
| Опознание по подписи `initData` | `src/web/walk_auth.py` — `safe_parse_webapp_init_data` из aiogram, срок подписи 24 часа |
| Тексты (ru, en) | `src/web/texts_walk.py`. Скрипт строк не содержит |
| Экран | `templates/walk.html`, `static/walk.js`, `static/walk.css` — токены дизайн-системы, тема из Telegram |
| Кнопка в боте | `keyboards.walk_keyboard`, `routers/start.py` |
| Заголовки | `security_headers.WALK_*`: в рамку пускает только `*.telegram.org`, скрипт — только свой и `telegram.org` |
| Запрос | `src/db/queries.py::previous_findings` |

**Доступ.** Адреса открыты без учётки админки (`auth.OPEN_ENDPOINTS`).
Опознаёт подпись Telegram, а показывается только проверка чата того, кто
открыл. Завести такую проверку может только бот, и решение, пускать ли
человека, бот уже принял. Отдельного списка допущенных у мини-аппа нет:
он разошёлся бы с ботом при первой же привязке учётки. Известное следствие:
у человека, которого отключили посреди проверки, экран его собственной
проверки откроется до её завершения.

## Настройка

| Переменная | Кто читает | Что делает |
|---|---|---|
| `BOT_WALK_URL` | бот | Адрес страницы, только `https://`. Пусто — кнопки нет |
| `TELEGRAM_BOT_TOKEN` | веб | Ключ для проверки подписи. Есть — мини-апп включён. Нет — адреса отвечают 404 |
| `WEB_WALK_PREVIEW_CHAT` | веб | **Только стенд:** открыть экран без подписи на этот чат. Вместе с токеном — отказ на старте |

## Стенд прототипа

Домашний сервер разработки, отдельный проект compose `decimus-walk`: сервисы
`db` и `web` из штатного `docker-compose.yml`, методика — синтетическая
`tests/methodology`, `WEB_WALK_PREVIEW_CHAT` на чат сида. Адрес стенда в
репозитории не записывается: он публичный, а стенд открыт без входа.

Картину стенда собирает `tools/seed_walk_stand.py`: прошлая проверка точки
«Тестоград-1» с четырьмя замечаниями и идущая проверка, где одно замечание
повторилось. Повторный запуск возвращает стенд к исходному виду.
