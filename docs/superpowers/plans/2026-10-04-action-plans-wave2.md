# Волна 2: экшн-планы — план

> План ведётся руками. Спека — `docs/superpowers/specs/2026-09-30-country-and-prescriptions-design.md`
> (D277). Решения: D263–D265, D267–D269, D272, D274, D282–D290. Задача #415 (Refs).

**Что получится.** После подтверждения проверки УК с D2 или D3 у партнёра этой
страны сам появляется запрос экшн-плана со сроком 7 дней. Партнёр в разделе
«Экшн-планы» загружает файл плана (любой формат). Сотрудник УК в своём разделе
видит очередь (ждут приёмки / просрочены), принимает план или возвращает с
обязательным комментарием, и партнёр загружает новую версию. Каждое действие
лежит в истории: кто, что, когда.

**Не входит:** предписания (волна 3), «Назначить проверку» (спека планов),
любые письма, сообщения в бот и уведомления людям — партнёр видит запрос на
экране, который открывает сам.

## Решения внутри волны (без владельца, инженерные)

| Вопрос | Как | Почему |
|---|---|---|
| Когда создаётся автозапрос | В той же транзакции, что подтверждение (`src/db/accept.py`), той же ролью администратора истории | Подтверждение без запроса невозможно: либо оба, либо ничего. Триггер в базе не годится — срок по умолчанию живёт в окружении, а не в схеме |
| Откуда «есть D2/D3» | Счётчики `inspections.counts`, которые положил движок при сливе или пересчёте на приёмке | Классы не пересчитываются (CLAUDE.md); счётчик — ответ движка |
| По каким проверкам | Только проверки пространства УК (`HQ`) | Экшн-план — ответ партнёра на проверку УК (D289). Собственные проверки партнёра запроса себе не порождают — развилка вынесена владельцу |
| Чья страна | Страна точки (`units.country`); партнёр видит запросы своих стран через охват (`reach.py`, D284) | Одна страна — один партнёр; пространство партнёра в запросе не дублируется, иначе два источника правды |
| «Просрочен» | Не хранится: срок прошёл, статус «запрошен» (в т. ч. возвращён без новой версии) | Спека, жизненный цикл |
| Кто что пишет в базе | Партнёр (роль приложения) — только загрузка версии; создание запроса, срок, приём и возврат — только администратор истории | Урок #490: роль приложения не может ни вставить «принятый» запрос, ни перевести его в «принят» — держат триггеры и гранты, не код |
| История | Таблица `action_plan_events`, пишет только триггер (`security definer`, `search_path` как в 0033) | Прямой записи нет ни у одной роли — историю нельзя ни пропустить, ни подделать |
| Файлы | Хранилище кадров, префикс `action-plans/`; отдаются только вложением, `nosniff` | Любой формат (D267): HTML, отданный как страница, — хранимый XSS |
| Предел | `ATTACHMENT_MAX_MB` (по умолчанию 25), только на маршруте загрузки | D269; остальные формы держат прежние 256 КБ |

## Задачи

1. **Миграция `0036_action_plans.sql`** — таблицы запросов, версий, вердиктов и
   истории; триггеры переходов и истории; права. Тесты базы до кода: роль
   приложения не вставляет запрос и вердикт, не переводит в «принят»; вставка
   сразу «принятым» — отказ любой роли; принятый не возвращается; загрузка
   только в «запрошен»; история пишется сама. Отпечаток и права — в
   `test_db_migrations_frozen.py` и `test_db_migrate_roles.py`.
2. **Ядро `src/db/action_plans.py`** — чистые функции (нужен ли запрос по
   счётчикам, просрочен ли, состояние для экрана) с тестами до кода; двери
   базы: автозапрос в подтверждении, ручной запрос, срок, загрузка, приём,
   возврат, чтение по охвату, выдача файла по охвату. Тесты: партнёр чужой
   страны не видит, не загружает, не скачивает; IDOR по id запроса и файла.
3. **Настройки** `ACTION_PLAN_DUE_DAYS` (7) и `ATTACHMENT_MAX_MB` (25).
4. **Веб**: раздел УК `actions` (`hq_only`, рабочее имя «Действия», #462) —
   очередь сверху, список запросов по стране, приём/возврат/срок; раздел
   партнёра `plans` («Экшн-планы») — свои запросы и загрузка; кнопка
   «Запросить экшн-план» на карточке проверки УК; скачивание версии; блок
   экшн-планов на экране страны. Тексты ru и en. Тесты заслонов на маршрутах.
5. **Доки и сдача**: `docs/12-web-admin.md`, `docs/08-deploy.md`, CHANGELOG;
   гейты `make fmt lint types dead bounds`; живой прогон пути из критерия
   приёмки на тестовой базе; PR.
