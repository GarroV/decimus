# Страна, предписания и экшн-планы

> Спека. Ведётся руками. Опирается на решения владельца D144, D237, D238 и
> D260–D276 (`docs/furca/decisions.md`). Задачи: #288 (статистика страны по
> её чек-листам), #462 (названия разделов), #463 (профиль страны), часть #423 (вход партнёра в своё
> пространство). Уточняет спеку предписаний от 28.09
> (`2026-09-28-remediation-plans-design.md`): её строковый конструктор плана
> откладывается (D265).
> Статус: **согласована владельцем** (30.09.2026, D277).

## Что строим

Веб сейчас отвечает на вопрос «как дела в сети»: «Обзор» и «Проверки» —
графики и статистика. Не хватает места, где **работают с конкретной страной**:
смотрят её пиццерии, видят, что по ней отправлено и что пришло в ответ, и
отсюда же действуют.

Строим три вещи:

1. **Экран «Страна»** — всё, что влияет на работу или несёт информацию по
   конкретной стране (D262). Один экран для УК и партнёра, партнёр видит
   только свои пиццерии.
2. **Раздел действий УК** — отдельный, виден только УК (D264): назначить
   проверку, отправить предписание, запросить экшн-план, принять или вернуть
   его.
3. **Действия партнёра** — у себя: видит пришедшие предписания и запросы,
   загружает файл экшн-плана (D263, D265).

«Обзор» и «Проверки» не меняются (D262).

**Критерий приёмки владельца.** На «Обзоре» клик по Батуми открывает страну
Грузия с раскрытой пиццерией Батуми-1 и её последней проверкой. В разделе
действий УК сотрудник запрашивает экшн-план по этой проверке. Партнёр Грузии
видит запрос у себя и загружает PDF. Сотрудник УК возвращает план с
комментарием «нет сроков»; партнёр загружает вторую версию, УК её принимает.
На экране страны у проверки видны обе версии, комментарий и отметка
«принят». Партнёр другой страны ничего из этого не видит, а набранный руками
адрес раздела УК отдаёт ему отказ.

## Словарь

| Слово | Что значит |
|---|---|
| **Страна** | Страна справочника пиццерий (`units.country`). Экран строится по ней, а не по тенанту: у партнёра может быть больше одной страны |
| **Предписание** | Официальное письмо УК партнёру: фиксация факта несоблюдения (плохие проверки, просрочка и подобное) и требование устранить в срок. Эскалация, когда договориться уже нельзя; не автоматический итог проверки (D266). В первой версии — вставленный текст, отправленный письмом (D270) |
| **Экшн-план** | Ответ партнёра на проверку: файл любого формата, привязанный к стране и к конкретной проверке (D265, D267). Конструктора плана в вебе нет |
| **Запрос экшн-плана** | «Пришлите план по этой проверке до такой-то даты». Появляется сам после подтверждения проверки с D2 или D3 (D272); по остальным проверкам — кнопкой УК. Срок ответа — настройкой, по умолчанию 7 дней от подтверждения; у запроса правится (D274) |
| **Версия плана** | Каждая загрузка — новая версия; старые не стираются |

## Экран «Страна»

Адрес `/country/<код>` (ключ раздела `country` уже есть в `sections.py`).
Без кода — колонка стран в охвате человека и справа сразу первая из них (D298).

**Шапка.** Выбор страны; фильтры — период, город, чек-лист, вид проверки.
Всё ниже пересчитывается под фильтры, результат на экране (D262 — это и есть
«выгрузка на промежуток»; файлов CSV/XLSX/PDF прототипа нет).

**Блоки, сверху вниз:**

1. **Пиццерии страны.** Строка на пиццерию: последняя проверка (дата,
   процент, буква), движение к предыдущей, экшн-план последней проверки
   (нет запроса / ждём / на приёмке / принят / вернули), действующие
   предписания, следующая плановая проверка. Клик по строке раскрывает
   историю проверок точки; из неё — карточка проверки и карточка пиццерии.
   Адрес `/country/<код>?unit=<id>` открывает экран с раскрытой точкой —
   сюда ведёт клик по городу или пиццерии на «Обзоре» (D260).
2. **Предписания страны.** Все предписания, отправленные партнёру по этой
   стране: дата, суть, срок, статус. Письмо открывается.
3. **Экшн-планы.** По проверкам страны: запрос, версии файлов, комментарии
   УК, итог. Файлы скачиваются.
4. **План проверок.** Проведено / запланировано за год — вид из спеки планов
   (D238). Партнёр видит свои плановые проверки тоже (D273); уведомление о
   них — черновиком в Gmail сотрудника УК, который назначил проверку: он
   проверяет адресатов и текст и отправляет сам (D276). До постройки планов блока нет (D217: экран
   показывает то, что есть).
5. **Что системно болит.** Пункты, которые валятся в нескольких пиццериях
   страны; зоны, где страна теряет больше всего. Считается через движок, по
   эталонному чек-листу (D144).
6. **Собственные чек-листы страны (#288).** Результаты по чек-листам,
   которые страна завела себе сама, отдельно от эталона — с ним не смешиваются
   (D144). До появления таких чек-листов блока нет.

На экране **нет действий УК**. Сотруднику УК виден переход «Действовать» в
раздел УК с этой страной; партнёру — «Мои запросы» в свой раздел.

## Раздел действий УК

Имя раздела — в #462; «вкладка УК» не имя (D264). Виден и открывается только
тенанту `HQ`. Страна выбирается фильтром, переход с экрана страны приходит с
ней. Действия:

| Действие | Что происходит |
|---|---|
| Назначить проверку | Создаёт плановую проверку (спека планов). До её постройки — не показывается |
| Запросить экшн-план | По проверке без D2/D3 — вручную, со сроком ответа; с D2/D3 запрос уже создан сам (D272). Партнёр видит запрос у себя |
| Принять план | Последняя версия помечается принятой; запрос закрыт |
| Вернуть план | Обязательный комментарий; запрос снова ждёт партнёра |
| Отправить предписание | Сотрудник выбирает страну, пиццерии (одна, несколько или вся страна), срок, проверки-основания и **вставляет текст письма** (D270). Письмо уходит так же, как письмо по проверке сегодня: черновиком в Gmail сотрудника (`src/web/google_mail.py`), отправляет он сам — письмо остаётся в его почте, копия текста и адресатов — в системе. Адресатов сотрудник вписывает сам, система запоминает их для страны и подставляет в следующий раз — так собираются контакты страны, первое поле её профиля (D275, #463). Письмо с подтягиванием нарушений и юридической обвязкой по договору партнёра — позже |
| Закрыть предписание | Требование выполнено или снято — с комментарием |

Над списком — очередь: что просрочено и что ждёт приёмки, по всем странам
или по выбранной.

## Действия партнёра

Видит только свои страны. Здесь:

- **Запросы экшн-плана** — по каким проверкам ждут план и до какого числа;
  загрузить файл (любой формат, D267); после возврата — загрузить новую
  версию. Комментарий УК виден у запроса.
- **Предписания** — пришедшие письма, срок, статус. Ответить на
  предписание партнёр может файлом и комментарием; закрывает его УК.

Действий УК здесь нет ни одного.

## Жизненные циклы

**Запрос экшн-плана**

Создаётся сам при подтверждении проверки с D2 или D3 (D272) или кнопкой УК.

```
запрошен ──(партнёр загрузил)──► на приёмке ──(УК принял)──► принят
    ▲                                 │
    └────────(УК вернул, комментарий)─┘
```

«Просрочен» не хранится, а считается: срок прошёл, а статус «запрошен» или
возвращён без новой версии.

**Предписание**

```
черновик ──(УК отправил)──► действует ──(УК закрыл, комментарий)──► закрыто
```

«Просрочено» — считается: срок прошёл, а предписание действует. Отправленное
письмо не правится: исправление — это закрытие с комментарием и новое
предписание.

## Данные

| Таблица | Поля |
|---|---|
| `action_plan_requests` | id, inspection_id, country, tenant партнёра, срок, кто и когда запросил, статус |
| `action_plan_files` | id, request_id, версия, ключ объекта в хранилище, имя файла, размер, тип, кто и когда загрузил |
| `action_plan_reviews` | id, file_id, вердикт (принят / вернули), комментарий, кто и когда |
| `prescriptions` | id, country, tenant партнёра, пиццерии (пусто = вся страна), основание, требование, срок, статус, кто и когда отправил, кто, когда и с каким комментарием закрыл |
| `prescription_inspections` | связь предписания с проверками-основаниями |
| `prescription_files` | вложения и ответы партнёра к предписанию — как `action_plan_files` |

Предел файла — 25 МБ, настройкой окружения (`ATTACHMENT_MAX_MB`), а не
константой: увеличить можно без правки кода (D269). Файлы лежат в
хранилище кадров на MUSPELHEIM (D268) отдельным префиксом; удаление кадров
после вычитки (D202) его не трогает. Бэкапа у хранилища нет (D259) — риск
принят тем же решением, что для фото.

Связь только кодами и id (конституция): страна — код справочника, пиццерия —
id точки, проверка — id проверки. Проценты и буквы на экране — только из
движка (`engine/audit.py`), не пересчитываются.

## Доступы

- Заслон — **на раздел целиком**, флагом в реестре разделов, как у «Людей»
  (`admin_only`); здесь нужен признак «только HQ». Скрытие пункта в панели не
  защита: каждый маршрут раздела УК отказывает не-HQ на сервере.
- Экран «Страна» и раздел партнёра отдают только страны и пиццерии тенанта
  человека. Файл скачивается только тем, чья это страна, и УК.
- Каждое действие пишется в историю: кто, что, когда.

## Зависимости и волны

**Зависимость.** Партнёр в вебе появляется с первой волной спеки чек-листов
(пространства, #423): сейчас веб работает в одном тенанте (`WEB_TENANT`). До
неё строится всё, что видит УК; сторона партнёра включается вместе с входом
партнёра.

| Волна | Что | Проверка |
|---|---|---|
| 1 | Экран «Страна» для УК: шапка с фильтрами, пиццерии с раскрытием, системные нарушения; клик по городу на «Обзоре» | Смоук по прод-копии: Батуми → Грузия, Батуми-1 раскрыта |
| 2 | Экшн-планы: запрос, загрузка, приём и возврат; раздел действий УК | Путь из критерия приёмки на стенде MUSPELHEIM |
| 3 | Предписания: письмо, закрытие, вложения | Отправить, закрыть, увидеть на экране страны |
| 4 | Сторона партнёра (после #423) | Партнёр видит своё и получает отказ на чужом |
| — | План проверок и «Назначить проверку» — по спеке планов; собственные чек-листы — по #288 | — |

Ядро с тестами до кода (правило тестирования): заслоны доступа и расчёт
«просрочено». Остальное — прогоном.

подтягиванием нарушений и юридической обвязкой (D270, позже); профиль
страны (#463); уведомления партнёру в бот (#414) — почтой уведомляются
только плановые проверки (D273); выгрузка файлами (D262); графики динамики на экране страны —
они на «Обзоре» (D262); названия разделов (#462).
