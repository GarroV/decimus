# Планы и календарь проверок

> Спека. Ведётся руками. Опирается на решения владельца D024, D134, D139,
> D141, D182, D228 и D238 (`docs/furca/decisions.md`). Задачи: #278 (логика
> календаря), #279 (годовой календарь в таблице), #409 (планирование
> периодом, а не датой), #309 (запланированные в «Проверках»), часть #416.
> Статус: **черновик на согласование владельцу** (28.09.2026).

## Что строим

Сотрудники УК планируют проверки пиццерий по странам. Сегодня план живёт в
таблице вне продукта, и продукт не знает, что проверка вообще ожидалась.
Строим одну сущность — **плановую проверку** — и два вида на неё:

- **«Планы»** (`/plans`) — годовая сетка страны: пиццерии × месяцы. Здесь
  план составляют и видят покрытие.
- **«Календарь»** (`/calendar`) — те же записи по датам и людям. Здесь видно,
  кто куда едет на этой неделе.

Оба раздела уже заведены в навигации и пока приглушены.

План составляется **руками** (D238): сотрудник УК сам ставит каждую проверку
в сетку. Нормы «N раз в год» нет, и покрытие показывается как «проведено /
запланировано». Чтобы ручной план на сотню точек не превращался в сто
кликов, есть массовое действие: выделить строки и поставить всем квартал.

**Критерий приёмки владельца.** Сотрудник УК открывает «Планы» → Сербия →
2027, выделяет десять пиццерий и ставит им «Q1, ответственный — Мария».
В сетке у каждой полоса на январь–март. Одной из них он назначает точную
дату 14.02 — в «Календаре» у Марии 14.02 стоит эта пиццерия. Аудитор
проводит проверку 14.02, её подтверждают — плановая запись становится
«проведена» с буквой проверки, без единого клика. Не проверенные к концу
марта становятся просроченными, и это видно в сетке красным.

## Словарь

| Слово | Значение |
|---|---|
| **Плановая проверка** | Запись «эту пиццерию проверяем в этом окне»: точка, чек-лист, вид, окно, ответственный |
| **Окно** | Месяц, квартал или точная дата (#409). Хранится двумя датами — начало и конец; у точной даты они совпадают |
| **Вид** | `planned` (плановая) или `repeat` (повторная) — те же коды, что у проведённой проверки (`src/domain/kinds.py`) |
| **Ответственный** | Человек из круга УК, который едет: выбор из списка, не свободный текст |
| **Покрытие** | «проведено / запланировано» за период: по стране, по месяцу, по человеку |

## Жизненный цикл

| Статус | Как попадает | Что видно |
|---|---|---|
| **запланирована** | заведена с окном «месяц» или «квартал» | полоса на окно |
| **назначена** | у записи появилась точная дата | точка на дату, в «Календаре» у человека |
| **проведена** | система связала её с подтверждённой проверкой | буква проверки, ссылка на карточку |
| **отменена** | человек, с обязательной причиной | зачёркнута, в покрытие не входит |

«Просрочена» — признак, а не статус: конец окна прошёл, а проверки нет.
Он вычисляется на лету, поэтому перенос окна его сразу снимает.

### Связь с проведённой проверкой — сама

При подтверждении проверки (этап приёмки, D199) система ищет плановую
запись **той же точки**, в окно которой попадает дата проверки и которая
ещё не проведена. Ищет сначала с тем же чек-листом, потом с любым. Нашлась
одна — связывает. Нашлось несколько — берёт с самым ранним окном. Не
нашлось ничего — проверка «вне плана»: в сетке она стоит отдельной меткой
и тоже входит в «проведено».

Отмечать проведение руками не нужно и нельзя: иначе появится два
источника правды о том, была ли проверка.

## Экраны

Раскладка по эталону Swarm (D228): сетка или список во всю ширину, запись
открывается панелью справа.

### `/plans` — годовая сетка страны

```
Планы   [Сербия ▾] [2027 ▾] [Ответственный ▾]              проведено 18 / запланировано 64
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ ☐ ПИЦЦЕРИЯ        янв  фев  мар  апр  май  июн  июл  авг  сен  окт  ноя  дек    ИТОГО   │
│ БЕЛГРАД                                                                                  │
│ ☐ Белград-1       ════Q1═════●A     ···            ════Q3═════                   1 / 2  │
│ ☐ Белград-2            ○14                              ○                        0 / 2  │
│ ☐ Белград-3       ══Q1════!══                                                    0 / 1  │
│ НОВИ-САД                                                                                 │
│ ☐ Нови-Сад-1                                                                     0 / 0  │
│ ───────────────────────────────────────────────────────────────────────────────────────  │
│ ПО МЕСЯЦАМ        2/5  3/4  4/9  …                                                      │
└──────────────────────────────────────────────────────────────────────────────────────────┘
выделено 3   [Поставить окно…] [Ответственный…] [Снять выделение]
```

- **Строки** — пиццерии страны из справочника (`units`), сгруппированные по
  городу. Колонки — 12 месяцев. Внизу итог по месяцам, справа — по точке.
- **Метки:** полоса — окно «квартал» или «месяц»; `○` — назначенная дата;
  `●A` — проведена, с буквой; `!` — просрочена; `···` — проверка вне плана.
- **Щелчок по пустой клетке** открывает панель заведения с окном «этот
  месяц»; щелчок по метке — панель записи.
- **Массовое действие:** флажки строк → «Поставить окно» (месяц или
  квартал, чек-лист, вид, ответственный) → по записи на каждую выделенную
  точку. Это ответ на «руками, но не сто кликов».
- Точка без единой записи на год видна пустой строкой с итогом `0 / 0`,
  а не спрятана. Так дыру в плане видно сразу.

### `/calendar` — по датам и людям

```
Календарь   [Сербия ▾] [Мария ▾]      ◂ Февраль 2027 ▸      [Месяц | Неделя | Список]
┌ пн ──── вт ──── ср ──── чт ──── пт ──── сб ──── вс ┐   Без даты в феврале (7)
│ ...                  │ 14 Белград-2 · Мария        │   Белград-1 · Q1 · Мария
│                                                    │   Белград-3 · Q1 · Иван
└────────────────────────────────────────────────────┘   …
```

- В сетке месяца — только записи с точной датой. Записи с окном без даты
  стоят списком справа: «без даты в этом месяце». Отсюда дату назначают
  перетаскиванием на день или полем в панели.
- Вид «Список» — он же основной на телефоне: по дням, ближайшие сверху.
- Отбор по стране и по человеку. «Мои» — отбор по себе.

### Панель записи

Пиццерия, чек-лист, вид, окно (месяц / квартал / дата), ответственный,
заметка. Внизу — связанная проверка (когда проведена) или «Отменить» с
причиной. История изменений — свёрнутым списком.

### Связи с другими разделами

- **«Обзор»:** кнопка «Назначить проверку» (сейчас приглушена) открывает
  панель заведения.
- **«Проверки» (#309):** срез «запланированные» — ближайшие назначенные.
- **Карточка пиццерии:** строка «следующая проверка: Q1 2027 · Мария».
- **Предписания** (`2026-09-28-remediation-plans-design.md`): в панели плана
  исправления — «Запланировать повторную», которая открывает заведение с
  видом `repeat` и окном после ближайшего срока.

## Данные

Новая таблица (миграция `00NN_planning.sql`), всё кодами:

| Колонка | Смысл |
|---|---|
| `id` | |
| `unit_id` | пиццерия (справочник `units`) |
| `checklist_code` | чек-лист (пара пространство+код, D183) |
| `kind` | `planned` / `repeat` |
| `window_start`, `window_end` | окно; у точной даты совпадают |
| `window_kind` | `month` / `quarter` / `date` — чтобы показать «Q1», а не «01.01–31.03» |
| `assignee` | человек из круга УК (ссылка на учётку) |
| `inspection_id` | связанная проведённая проверка, null пока нет |
| `cancelled_at`, `cancelled_reason` | отмена |
| `created_by`, `created_at`, `note` | |

Плюс `planning_events` для истории: кто, что, когда. Статус не хранится —
он выводится из полей (`inspection_id`, `cancelled_at`, `window_kind`), так
что рассогласоваться ему не с чем.

- Страна берётся от точки (`units.country`). Отдельного справочника стран
  не заводим (#378 — нормализация городов, отдельная задача).
- Покрытие считается запросом, не хранится.

## Кто что делает

План составляет УК: разделы видит пространство `hq`. Партнёру свои
плановые проверки не показываются, пока не решено иначе. Назначение
проверки партнёру (D024, #416) — отдельная фича, которая встанет на ту же
таблицу.

## Заслоны

- Окно с концом раньше начала → отказ.
- Точная дата вне выбранного года сетки → запись сохраняется, сетка
  предупреждает, что запись ушла в другой год.
- Отмена без причины → отказ.
- Ручная отметка «проведена» не существует ни в интерфейсе, ни в API.
- Удаление проведённой записи → отказ (только отмена непроведённой).
- Пространство не `hq` → разделы открываются пустыми с объяснением, данные
  не отдаются (граница на сервере).
