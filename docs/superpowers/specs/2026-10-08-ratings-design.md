# Рейтинги РС и РКО

> Спека. Ведётся руками. Опирается на решения владельца D317–D329
> (`docs/furca/decisions.md`). Задача: #548. Эталон — сводка Apps Script
> «Controlling IMF Analytics» (D324). Статус: **строится без отдельного
> согласования** (D329).

## Что строим

Контроль УК сейчас ведёт рейтинги в двух Google-таблицах и показывает их
сводкой из Apps Script. Таблицы заполняются руками и выгрузками, сводка
живёт отдельно от продукта. Строим то же самое внутри Decimus, первым
кирпичом будущей «страницы здоровья пиццерии» (туда потом придут Pointer и
другие оценки):

1. **Хранилище рейтингов** — отдельная схема `ratings` в базе Decimus. Данные
   проверок Decimus и рейтингов не смешиваются (D321).
2. **Коннектор загрузки** — один разборщик, два входа: форма в вебе и
   MCP-инструмент, чтобы файл мог загрузить Claude (D320).
3. **Раздел «Рейтинги»** в веб-админке. Его видят все: УК и любой партнёр
   (D327). Блоки — как в сводке скрипта (D324).
4. **Роль «контроль»** — загружает данные, правит справочники рейтингов. Чек-
   листы, методику и пользователей не меняет (D319): методику он видит на чтение, как аудитор УК.

Охват — страны IMF: всё, кроме России, Казахстана и Узбекистана (D318).

**Критерий приёмки владельца.** На стенде MUSPELHEIM сотрудник с ролью
«контроль» загружает в веб три выгрузки (`rko-violations`, `rko-evaluations`,
`rs-checkups`). Claude через MCP загружает снимок с рейтинга. Повторная
загрузка тех же файлов ничего не дублирует, и журнал загрузок это
показывает. В «Рейтингах» выбор «Бизнес-девелопер → Василий Гарро, период
Q3» показывает Slovenia, Serbia и Bulgaria со средним РС и РКО и дельтой.
Ниже идут топ-5 нарушений по кластеру и по стране, Top/Bottom-10 пиццерий,
хард-нарушения и зона риска. Цифры сходятся со сводкой скрипта за тот же
период с точностью до округления, а каждое расхождение объяснено. Партнёр
Грузии видит ту же страницу целиком, но формы загрузки и справочников у него
нет. Набранный руками адрес загрузки отдаёт ему отказ.

## Словарь

- **РС** — рейтинг стандартов: проверки инспектором или онлайн, период —
  полумесяц («Сентябрь 2 часть 2026»).
- **РКО** — рейтинг клиентского опыта: фото заказов (доставка, ресторан),
  период — неделя.
- **Период рейтинга** — период, за который Dodo IS считает оценку. Хранится с
  датами начала и конца и с названием на RU и EN.
- **Период отчёта** — что выбрал человек: месяц, квартал или «по рейтингу»
  (один период рейтинга). Оценка за месяц или квартал — среднее оценок
  пиццерии за периоды рейтинга, которые начались внутри него.
- **Хард-нарушение** — нарушение из списка, который ведёт контроль (D328).
  Для РС стартовый список: уровень D3, критичные, обнуление. Для РКО:
  «Критично белое дно», «Пиццу привезли холодной», «Нарушен рецепт»,
  «Сильно деформирована», «Все борты белые», «Дисквалифицировать пиццу».
- **Зона риска** — три последних периода рейтинга подряд ниже порога. Порог
  по умолчанию 85, это настройка контроля.
- **Кластер** — страны одного бизнес-девелопера.

## Источники

Что доступно сейчас (D325):

| Вход | Что внутри | Ключ строки |
|---|---|---|
| `rko-violations_*.csv` | Фото-проверка РКО: пиццерия, нарушения (`; `), «другие проблемы», тип (доставка или ресторан), ссылки | `checkupId` |
| `rko-evaluations_*.csv` | Приёмка фото РКО: принято или отклонено, конвейер, страна | `CheckupId` |
| `rs-checkups_*.csv` | Проверки РС: пиццерия, дата, формат (инспекция или онлайн), длительность, ссылки. Колонка «Баллы» в выгрузке пустая | id в ссылке на отчёт |
| Снимок рейтинга (JSON) | Claude забирает его со страницы рейтинга Dodo IS в браузере сотрудника. Состав: оценки РС и РКО по пиццериям, история периодов, замечания с критериями | id пиццерии и id периода |
| Выгрузка листа «Качество по пиццериям» (CSV) | Оценка пиццерии по периодам из таблиц контроля. Нужна, пока снимка нет | пиццерия и период |

Формат файла разборщик узнаёт по заголовку, имя файла не важно. Чего нет
ни в одном файле: оценки по отдельной проверке и фото. Оценки берутся из
снимка или из таблиц. Для фото — ссылка на проверку в Dodo IS.

Прямой доступ сервера к API рейтинга — будущий вход того же разборщика.
Вопрос о нём решается на встрече (D325).

Россия, Казахстан и Узбекистан отбрасываются по стране, а не по «Конвейеру»:
у части стран IMF конвейер в выгрузке пустой.

## Пиццерия

Ключ — id пиццерии Dodo IS (32 hex). Он есть в ссылке `dodopizza.info/
rating#/<id>/…` во всех трёх CSV и в снимке. Названия:

- хранятся с нормализацией (`normalize_unit_name`);
- имя без id сопоставляется нечётко тем же разбором, что в боте
  (`src/domain/unit_name.py`);
- то, что не сопоставилось, загрузка не теряет: такие строки показываются
  контролю в журнале загрузки (D323).

Связь со справочником Decimus (`units`) — колонка `decimus_unit_id`. Её
заполнение — отдельная задача, вместе со справочником точек (#312).

## Хранилище

Схема `ratings` в той же базе, своими миграциями в общей последовательности.
Политик пространств (RLS по `tenant_code`) в ней нет: рейтинги видят все
(D327). Писать в схему может только роль приложения, через функции загрузки.

| Таблица | Что | Ключ |
|---|---|---|
| `ratings.units` | Пиццерия рейтинга: `dodo_id`, `name`, `name_normalized`, `country`, `decimus_unit_id` | `dodo_id` |
| `ratings.countries` | Страна: код ISO, название, бизнес-девелопер, входит ли в IMF | код |
| `ratings.periods` | Период рейтинга: тип (РС/РКО), `dodo_id`, начало, конец, названия RU/EN | тип + `dodo_id` или начало |
| `ratings.scores` | Оценка пиццерии за период: балл, статус расчёта, источник | пиццерия + тип + период |
| `ratings.checkups` | Проверка: тип, пиццерия, дата, формат или канал, приёмка, ссылки | тип + id проверки |
| `ratings.violations` | Нарушение в проверке или в замечаниях периода: текст, критерий, уровень, найдено ИИ/ML, вычет | проверка + текст |
| `ratings.hard_rules` | Список хард-нарушений: тип, текст или уровень | тип + правило |
| `ratings.settings` | Пороги: Top/Bottom (85), зона риска (85, 3 периода) | ключ |
| `ratings.imports` | Журнал загрузок: кто, когда, вход (веб/MCP), формат, sha256 файла, строк принято, обновлено, пропущено, не сопоставлено | id |

Загрузка идёт одной транзакцией: либо файл лёг весь, либо ничего. Тот же
sha256 повторно не грузится, журнал отвечает «уже загружен <дата>».
Пересекающийся по строкам файл обновляет строки по ключу, а не множит их.

## Коннектор загрузки

Один модуль `src/ratings/importer.py`. На входе байты и формат, на выходе
отчёт загрузки. Его вызывают:

- **веб**: `POST /ratings/import`, форма `multipart`, лимит 25 МБ, только
  «контроль» и админ УК;
- **MCP**: инструмент `import_ratings(kind, content)`. Для снимка — частями
  до 300 000 байт (`MCP_CHUNK_BYTES`; предел тела MCP 1 МБ, а кириллица может уйти в `\uXXXX`), каждая часть сама по себе целая. Токен
  только пространства УК.

Снимок рейтинга Claude собирает по описанной процедуре
(`docs/15-ratings.md`). Сотрудник контроля открывает рейтинг в своём
браузере, Claude читает данные и отдаёт их в `import_ratings`. Свой вход в
Dodo IS сервер не хранит и не использует.

## Раздел «Рейтинги»

Раскладка как везде (D296). Сверху отбор:

- группировка: бизнес-девелопер, страна или весь IMF;
- значение;
- период: месяц, квартал или период рейтинга.

Ниже блоки сводки (D324):

1. **Средний РС и РКО по странам** выбранной группы, итог группы и дельта к
   прошлому такому же периоду. Ячейка зелёная при дельте ≥ 0 и красная при
   < 0, как в скрипте.
2. **Нарушения РКО** — «Топ-5 по кластеру» и «По каждой стране»: всего
   нарушений, на одну проверку, топ-5 с числом.
3. **Нарушения РС** — то же. Источник: замечания из снимка.
4. **По проверкам РС** — Top-10 (> порога) и Bottom-10 (≤ порога), имя
   пиццерии ведёт на её страницу в рейтинге Dodo IS.
5. **Хард-нарушения РС** — D3, критичные, обнуления, построчно с пиццерией.
6. **По проверкам РКО** — Top/Bottom-10.
7. **Хард-нарушения РКО**.
8. **Пиццерии в зоне риска**.

Пустой блок пишет, почему он пуст: «за период нет данных РС» или «нарушений
не найдено». Пустых таблиц нет. Шапка сводки показывает, по какой загрузке
построены данные, и дату последней загрузки каждого источника.

Подраздел **«Загрузки»** (только «контроль» и админ УК): форма загрузки,
журнал, несопоставленные строки, справочник «страна → девелопер», список
хард-нарушений, пороги.

Тексты — на RU и EN с первой версии (`texts_ratings.py`). Названия
нарушений идут как в источнике: их переводит Dodo IS.

## Роль «контроль»

Новое значение роли веб-учётки `control`, наряду с `auditor` и `admin`.
Миграция расширяет check и права. Бывает только в пространстве УК.

| Что | контроль | аудитор УК | админ УК | партнёр |
|---|---|---|---|---|
| Видеть «Рейтинги» | да | да | да | да |
| Загружать, править справочники рейтингов | да | нет | да | нет |
| Чек-листы, методика, веса, пользователи | нет | как сейчас | как сейчас | как сейчас |

Остальные разделы для «контроля» открыты так же, как аудитору УК, на чтение.

## Чего нет в этой версии

- Ответы и отзывы клиентов (D322).
- Фото: только ссылка на проверку в Dodo IS.
- Прямой забор из API рейтинга (D325).
- Pointer и общая страница здоровья пиццерии (#251).
- Связь с пиццериями и проверками Decimus.

## Проверка

- **Ядро — тесты до кода:** разбор каждого формата, нормализация и
  сопоставление, идемпотентность, расчёт средних, дельты, Top/Bottom и зоны
  риска. Каждый тест прогоняется на испорченной копии файла.
- **Остальное — запуском:**
  - загрузка трёх настоящих CSV и снимка на стенде MUSPELHEIM;
  - сверка блока 1 со сводкой скрипта за Q3 по кластеру Гарро;
  - проход партнёром: страница видна, загрузка — отказ.
- **Регрессия:** `make check`, эталоны движка `belgrade-1/2` не меняются.
