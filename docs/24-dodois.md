## Как это устроено в целом

Dodo IS отдаёт данные по странам. Мы ходим к нему **не ключом одной общей учётки, а входом учётки каждой страны**:
коллега страны один раз подтверждает вход по ссылке, ключи входа ложатся в базу зашифрованными, дальше всё идёт само.
Два вывода: пока вход страны жив, данные страны собираются; умер вход (истёк, отозван, учётку закрыли) — собирать
нечем, и чинится это **новой ссылкой**, а не правкой кода.

| Часть | Где в коде | Что делает |
|---|---|---|
| Вкладка «Dodo IS» | `src/web/dodois_screen.py`, `templates/administration/dodois.html` | список стран, выпуск и отзыв ссылок, «Проверить сейчас», «Отключить», ключи приложения; только главный админ |
| Публичная страница ссылки | `src/web/dodois_connect.py` | коллега страны подтверждает вход кодом с экрана |
| Правила (ядро, без сети и базы) | `src/domain/dodois.py` | контуры и хосты, права входа, состояния, когда пора продлевать, цвет строки |
| Единственная точка сети | `src/dodois/client.py` | device flow, продление, userinfo, список пиццерий, стопы, `api_get`; только `GET` к API |
| Состояние входа по ссылке | `src/dodois/flow.py` | идущий вход в памяти процесса веба, погашение ссылки |
| Продление и проверка | `src/dodois/service.py` | ночью обновляет ключи, раз в час считает «открыто X из Y» |
| Сбор данных для «Качества» | `src/dodois/metrics.py`, `src/domain/dodois_metrics.py` | продажи, агрегаторы, оценки клиентов, РКО/РС и счёт проверок по пиццериям и месяцам |
| База | `src/db/dodois_logins.py`, `src/db/dodois_metrics_store.py`, `src/db/dodois_metrics.py` | вход и приглашения; запись и чтение метрик |

Ключи по имени: пара ключей приложения маркетплейса — `dodois.client_id`, `dodois.client_secret` (в `vault.secrets`
или, если там нет, в окружении `DODOIS_CLIENT_ID`, `DODOIS_CLIENT_SECRET`; реестр — `src/domain/service_keys.py`);
ключи входа каждой страны — `dodois.access.<cc>` и `dodois.refresh.<cc>` (`<cc>` — две строчные латинские буквы).
Всё в `vault.secrets` зашифровано ключом `SECRETS_KEY`, который лежит вне базы (в `.env` сервера). Значений ключей
в документах, журналах и ответах нет.

## Контуры и хосты (D729, D731)

Страны лежат на двух серверах Dodo IS; пути и права одни, пара ключей приложения одна.

| Контур | Код | Вход (auth) | API | Страны по умолчанию |
|---|---|---|---|---|
| Международный | `intl` | `auth.dodois.com` | `api.dodois.com` | все остальные |
| СНГ | `cis` | `auth.dodois.io` | `api.dodois.io` | BY, KG, TJ (`CIS_COUNTRIES` в `src/domain/dodois.py`) |

Контур выбирает главный админ при выдаче ссылки (`dodois.invites.contour`, миграция `0125`); умолчание — только
подсказка в форме. Контур входа (`dodois.logins.contour`) берётся из приглашения. Список работающих пиццерий страны
берётся без ключа с публичного адреса `publicapi.dodois.io`. Признак ошибки контура: вход по ссылке не того контура даёт
`unauthorized`, по ссылке нужного — `ok` (так и нашли Беларусь, D731).


## Вкладка «Dodo IS»: входы по странам (D640b, D641, #951)

Данные Dodo IS по странам берутся через вход учётки каждой страны (OAuth2, device flow
`auth.dodois.com` или `auth.dodois.io` — контур, D729), а не через ключ приложения одной учётки. Вкладка `/administration?tab=dodois`
(`templates/administration/dodois.html`; с D641 отдельная, раньше — блок во вкладке «Подключения»; в столбце стоит под «Подключениями»; с D653 — на общем каркасе вкладок, см. «Каркас вкладки администрирования» в [`27-web-administration.md`](27-web-administration.md): шапка с «?», раздел «Ключи приложения», **страны плитками** `sdtiles` (D655) — код страны, название, огонёк (зелёный — вход в порядке, красный — сбой, серый — входа нет), у подключённой — учётка Dodo IS, за которой вход (имя, без имени почта; длинная обрезается, целиком в подсказке), и «контур СНГ» по самому входу; «через кого подключено» (имя и почта подтвердившего, «Владелец (перенесённый вход)» для переноса, прочерк — входа нет) — в панели; кнопок в плитках нет, плитка открывает справа панель страны `?country=<код>` с «Сгенерировать ссылку», «Проверить сейчас» (есть вход), «Отключить» (есть вход; с подтверждением) и «Отозвать» (есть живая ссылка); все страны сети из справочника пиццерий, у страны без входа «Входа нет»; новая ссылка страны в той же транзакции отзывает её прежние живые ссылки, поэтому живая ссылка всегда одна; плитка здоровья страны ведёт на `?tab=dodois&country=<страна>`) отвечает на вопрос «чьим входом открыта каждая страна и
жив ли он»; видит и действует только главный админ (остальным 404, как у соседних блоков).
Загрузка продаж, стопов и доставки сюда не входит — только входы и их здоровье. Права входа:
`openid profile email shared sales stopsales deliverystatistics productionefficiency
offline_access`; данных людей Dodo IS мы не берём, к `api.dodois.com` / `api.dodois.io` — только `GET`.

**Контур (D729).** Страны лежат на двух серверах Dodo IS: международном (`dodois.com`) и СНГ (`dodois.io`); пути и права одни, одна пара ключей приложения принимается обоими. Какой контур у страны, публичные данные не говорят, поэтому его выбирает главный админ в панели страны рядом с «Сгенерировать ссылку» (список «Контур Dodo IS»; по умолчанию Беларусь, Кыргызстан и Таджикистан — СНГ, остальные — международный, `rules.CIS_COUNTRIES`). Контур хранится в приглашении (`dodois.invites.contour`, `0125`), страница по ссылке ведёт вход на его сервер и пишет хост мелким текстом, вход страны (`dodois.logins.contour`) берёт контур из приглашения, а сбор, продление и проверка ходят на контур входа. У плитки страны СНГ — пометка «контур СНГ». Если вход удался, а открыто 0 пиццерий, причина входа — «none_open» с подсказкой выдать новую ссылку с другим контуром.

**Как привязывается страна.** Кнопки «Подключить» с входом самого админа нет. Главный админ
нажимает «Сгенерировать ссылку» в панели страны и выпускает **одноразовую ссылку-приглашение** (живёт 24 часа); отправляет её
коллеге страны сам, из приложения ничего никому не уходит. Коллега открывает ссылку (публичная
страница без входа в decimus), нажимает «Начать» и подтверждает вход на сайте Dodo IS своего контура (`auth.dodois.com` или `auth.dodois.io`, хост написан на странице) кодом
с экрана. Сервер сам опрашивает Dodo IS, пишет вход страны (ключи — в `vault.secrets`), гасит
ссылку и пишет в журнал действий «вход Dodo IS по ссылке» от имени выдавшего (`credential=invite:<№>`).
Вход страны один, но **новый вход не затирает рабочий вслепую**: если у страны уже есть вход,
новая пара сначала проверяется — учётка должна открывать хоть одну пиццерию. Открывает —
заменяет прежний; нет — прежняя пара остаётся, ссылка гасится с исходом «не применён», у
страны и в списке ссылок видно «новый вход не дал доступа ни к одной пиццерии — не применён»
и имя учётки (миграция `0097`). При выдаче ссылки на страну с живым входом админ видит
предупреждение «подключение заменит текущий вход (кто, когда)». Ссылку можно отозвать, пока
она жива.

| Что | Как |
|---|---|
| Строка страны | страна, чьим входом открыта (имя и почта, источник «по ссылке» или «перенос»), «открыто X из Y пиццерий», время проверки и продления, состояние: `ok` / `partial` (открыто не всё) / `expired` (вход истёк, нужна новая ссылка) / `failed` (нет связи или запись не легла, повтор сам). Цвет — `domain.health.Status`, причина — `health.reason.dodois_*` |
| Хранение | схема `dodois` (миграции `0096`, `0097`): `logins` (вход страны, без ключей), `invites` (хэш токена SHA-256, срок, погашена, отозвана, исход «не применён» с именем учётки). Ключи — `vault.secrets`, имена `dodois.access.<cc>`, `dodois.refresh.<cc>` (cc строчные; имена закрыты `check`), шифртекст AES-256-GCM с именем в AAD. Пара заменяется атомарно: refresh-токен одноразовый, сбой записи не оставляет половину |
| Продление | фоновая задача бота `src/bot/dodois_loader.py` под замком `job_lock` (`DODOIS_LOADER_LOCK_KEY`): ночью (01:00–06:00 UTC) раз в сутки обновляет ключи, истёкший ключ доступа — в любой час; раз в час проверяет «открыто X из Y» (`unitinfo`, пачками по 30, `NoAccessToUnit` делит пачку). Отказ в продлении (`invalid_grant`) — «вход истёк», сбой связи — «не удалось связаться», вход не теряется. Если Dodo IS выдал новую пару, а база её не приняла, пара держится в памяти бота и запись повторяется на каждом следующем заходе (раз в час) раньше, чем бот снова пойдёт в Dodo IS: состояние «запись не легла, повторяем», а не «вход истёк». Перезапуск бота эту пару теряет — тогда нужна новая ссылка |
| Ключи приложения (D649) | первый блок вкладки — «Маркетплейс Dodo IS: ключи приложения Decimus» над странами, сжатый (D651): одна строка состояния и значений «••••», кнопки «Заменить» (форма раскрывается по клику) и «Удалить», без абзацев пояснений (макрос `key_panel(..., compact=true)`): сервис `dodois` реестра (`client_id`, `client_secret`, запасной путь `DODOIS_CLIENT_ID` / `DODOIS_CLIENT_SECRET`) — одна пара на все страны. Панель та же, что у «Ключей сервисов» (`users/_service_key_panel.html`), те же POST-адреса `/administration/connections/keys/dodois/{check,save,delete}` и заслоны (`connections_screen._key_action`); форма несёт скрытое поле `back=dodois`, ответ — эта же вкладка (`connections_screen.return_tab`: только известные вкладки, остальное — «Подключения»). На «Подключениях» этой пары больше нет. Пока пары нет, над таблицей стран — «Сначала задайте ключи приложения из маркетплейса»; без них ссылка выдаётся, но коллега на странице ссылки получает отказ «сервис ещё не настроен» |
| «Проверить сейчас» | в панели страны: `POST /administration/dodois/<страна>/check` — продление и счёт сразу; роль и происхождение, подтверждения входа не требует (ключей не показывает и не меняет) |
| «Отключить» | в панели страны, за подтверждением (`sconfirm`): `POST /administration/dodois/<страна>/disconnect` (#1551) — одной транзакцией удаляет вход (`dodois.logins`) и оба ключа (`vault.secrets`) и отзывает живые ссылки страны; загруженные показатели (`dodois.unit_*`, `dodois.metric_loads`) остаются. Ежечасные продление и проверка и сбор показателей страну просто пропускают (`replace_tokens` и `record_state` только обновляют существующую строку и вход не воскрешают). Страну можно подключить заново новой ссылкой. В журнале — «Отключён вход в Dodo IS». Роль и происхождение; в демо закрыто. Право `delete` на `dodois.logins` у роли администратора истории — миграция `0126` |
| Перенос готового входа | `tools/dodois_import.py --country XX --by <логин>` читает JSON с ключами из stdin, пишет как вход владельца (источник «перенос»), печатает только состояние и «открыто X из Y»; продление при переносе идёт под тем же замком, что у бота (`DODOIS_LOADER_LOCK_KEY`), занят — перенос просит повторить позже |
| Оповещения | сбой входа любой страны — сообщение владельцу, см. «Оповещения о смене состояния подключений» в [`27-web-administration.md`](27-web-administration.md) |

**Публичная страница ссылки** (`/dodois/connect/<токен>`, `src/web/dodois_connect.py`, без входа в
decimus; `dodois-connect.js` опрашивает её `status`). Заслоны: токен ищется по хэшу, сверка за
постоянное время; любая негодная ссылка (чужая, просроченная, погашенная, отозванная, неверной
формы) — один и тот же нейтральный 404; предел попыток по адресу (`web_throttle.address_verdict`,
порог 20 неудач, свой счёт `web_throttle.link_address_verdict`, не общий с паролем и API); `Cache-Control: no-store`, `Referrer-Policy: same-origin` (не `no-referrer`: при нём POST кнопки уходит с `Origin: null` и падает 403); сторонних ресурсов
нет; **GET ничего не запускает** — вход начинает только `POST …/start`, чтобы бот-превью почты не
сжёг ссылку; в демо закрыта. `POST …/start` сначала пробует шифрование (нет рабочего ключа
шифрования — отказ «не настроен» до обращения к Dodo IS), затем под замком ставит заглушку
входа: параллельные нажатия получают тот же вход, а не заводят свои потоки; на одну ссылку —
не больше 5 удачных начал, одновременно не больше 64 входов. Ссылка привязана к стране и гасится атомарно в той же транзакции,
что запись входа.

Адреса: `POST /administration/dodois/invite` (выпуск), `POST
/administration/dodois/invite/<№>/revoke`, `POST
/administration/dodois/<страна>/check`, публичные `GET /dodois/connect/<токен>`,
`POST /dodois/connect/<токен>/start`, `GET /dodois/connect/<токен>/status`. Выпуск проходит
свои заслоны (D716, заменило D715): роль главного админа → происхождение → предел попыток.
Второго шага, свежего входа и ключа доступа нет: админка у одного человека, а ссылка сама к данным
не пускает. Ключи приложения (блок выше) идут
прежними заслонами ключей сервисов. Отзыв и «Проверить сейчас» — роль и происхождение. Код —
`src/domain/dodois.py` (правила, ядро), `src/dodois/` (`client.py` — единственная точка сети,
`service.py`, `flow.py` — состояние входа по ссылке), `src/db/dodois_logins.py`,
`src/web/dodois_screen.py`, `src/web/dodois_connect.py`, тексты — `src/web/texts_dodois.py`.
Ключи (`client_secret`, `access_token`, `refresh_token`, код устройства) нигде не печатаются
и не логируются: ни в журнал действий, ни в журнал процесса, ни в исключения, ни в HTML
(`tests/test_dodois_no_secret_leak.py`).


## Фоновые задачи Dodo IS

Обе живут в процессе `bot` (`src/bot/app.py` запускает их при старте), каждая — под замком базы (`job_lock`): если заход
уже ведёт другой процесс, этот пропускается без ошибки.

| Задача | Файл | Частота | Замок | Что пишет | Где видно сбой |
|---|---|---|---|---|---|
| Продление и проверка входов | `src/bot/dodois_loader.py` → `service.run_pass` | раз в час (`CHECK_EVERY`); продление — ночью 01:00–06:00 UTC раз в сутки (ключ доступа живёт сутки, продлевается не чаще раза в 20 часов), истёкший ключ — в любой час | `DODOIS_LOADER_LOCK_KEY` = 951_0001 | `dodois.logins`: состояние, причина, «открыто X из Y», время продления и проверки | строка страны на вкладке «Dodo IS», плитка «Dodo IS по странам» на «Подключениях», оповещение владельцу при смене состояния ([`27-web-administration.md`](27-web-administration.md)) |
| Сбор данных для «Качества» | `src/bot/dodois_metrics_loader.py` → `metrics.run_pass` | заход раз в час (`CHECK_EVERY`); страна собирается, если последняя удачная загрузка вида старше 20 часов | `DODOIS_METRICS_LOCK_KEY` = 671_0001 | таблицы `dodois.unit_*`, журнал `dodois.metric_loads` | **только журнал и лог бота** — оповещения и плитки у этой задачи нет (люди узнают по пустым ячейкам «Качества») |

Сбор метрик ключей **не продлевает** — это делает только `service.run_pass`; страна с истёкшим входом пропускается молча.
Месяц заменяется целиком для пиццерий, ответивших в заход. Первая удачная загрузка вида берёт 12 полных месяцев и текущий,
дальше — прошлый и текущий.

## Метрики для «Качества» (D671)

Что собирается, четыре вида (`kind` в журнале):

| Вид | Что | Откуда (путь API) | Куда ложится |
|---|---|---|---|
| `sales` | заказы и выручка по источнику заказа и каналу, за месяц | `finances/sales/units` | `dodois.unit_sales_month` |
| `aggregators` | заказы из агрегаторов за месяц (свёртка, строк заказов не хранится) | `accounting/sales` с `orderSource=Aggregator` | `dodois.unit_aggregator_month` |
| `kr` | среднее и число оценок клиентов, зал и доставка | `customer-feedback/customer-ratings` | `dodois.unit_kr_month` |
| `ratings` | РКО и РС по неделям и число проверок | `controlling/ratings/customer-experience/history`, `.../standards/history`, `controlling/checkups` | `dodois.unit_rating_period`, `dodois.unit_checkup_period` |

Как эти числа превращаются в страницу — `docs/21-quality.md`; продажи также читает API для Swarm (`GET /api/v1/sales`,
[`31-swarm-api.md`](31-swarm-api.md)). Данных людей Dodo IS и строк заказов в базе нет.

## Таблицы схемы `dodois`

Создана миграциями `0096`, `0097`, `0105`, `0125`, `0126`. Ключа пиццерии везде — `dodo_id` (32 шестнадцатеричных знака).

| Таблица | Зачем | Кто пишет |
|---|---|---|
| `dodois.logins` | по строке на страну: контур, источник («по ссылке» / «перенос»), кто выдал и кто подтвердил, права, «открыто X из Y», время продления и проверки, состояние `ok` / `partial` / `expired` / `failed`, причина; **ключей нет** | веб (роль администратора истории) и бот |
| `dodois.invites` | приглашения: хэш токена SHA-256, срок 24 часа, погашена, отозвана, исход «не применён» с именем учётки, контур | веб |
| `dodois.metric_loads` | журнал сбора метрик: страна, вид, начало и конец, `ok`, текст отказа (вид отказа без значений ответа), число строк | бот |
| `dodois.unit_sales_month` | продажи пиццерии за месяц по источнику и каналу | бот |
| `dodois.unit_aggregator_month` | заказы из агрегаторов за месяц | бот |
| `dodois.unit_kr_month` | оценки клиентов за месяц | бот |
| `dodois.unit_rating_period` | РКО и РС по периодам, процент 0–100 | бот |
| `dodois.unit_checkup_period` | число проверок по периодам и статусам | бот |

Ключи входов лежат не здесь, а в `vault.secrets` (миграция `0096` разрешает имена `dodois.*`).

## Собрать страну вручную

**Готовой команды нет.** Бот собирает сам раз в час; ручного запуска у задачи нет, и #1572 просит его завести. Сейчас так
делают: `metrics.collect_country(...)` в контейнере бота, под служебным пространством. Пример для страны `RS` (подставить
свою; читает базу и ходит в Dodo IS только `GET`-ами, печатает исход каждого вида):

```bash
docker exec decimus-bot-1 python -c "
from datetime import UTC, datetime
from src.db import dodois_logins as logins
from src.db.space import SYSTEM_SPACE, acting_space
from src.dodois import metrics
with acting_space(SYSTEM_SPACE):
    login = logins.get_login('RS')
    print(metrics.collect_country(login, list(metrics.parse.KINDS), today=datetime.now(UTC).date()))
"
```

Вместо списка видов можно взять один: `['sales']`, `['aggregators']`, `['kr']`, `['ratings']`. Ответ — список исходов
`Outcome(country, kind, ok, rows, error)`; то же самое легло в `dodois.metric_loads`. Если входа страны нет, `get_login`
вернёт `None`, и сначала нужна ссылка. Продлить или проверить **вход** (а не метрики) вручную — кнопка «Проверить сейчас» в
панели страны; перенести готовый вход — `tools/dodois_import.py`.

## Где видно сбой

1. **Вкладка «Администрирование → Dodo IS»**: строка страны, цвет и причина словами (`src/web/texts_dodois.py`,
   ключи `dodois.reason.*`); состояния: «Работает», «Открыто не всё», «Вход истёк», «Сбой связи», «Входа нет».
2. **«Подключения» → «Состояние подключений» → «Dodo IS по странам»**: плитка на страну, ссылка на вкладку.
3. **Сообщение владельцу в канал FURCA** при смене цвета входа страны (раз в час), описано в
   [`27-web-administration.md`](27-web-administration.md).
4. **Журнал сбора метрик** (у него других признаков нет):

   ```bash
   cd /srv/decimus && docker compose -f docker-compose.yml -f docker-compose.prod.yml exec -T db \
     psql -U dodo_audit -d dodo_audit_service -c \
     "select country, kind, started_at, ok, rows, error from dodois.metric_loads order by started_at desc limit 20"
   ```

5. **Лог бота**: `docker logs decimus-bot-1 2>&1 | grep "Dodo IS"` — строки «сбор не удался (…)», «заход пропущен», «проверка упала».

| Причина (`reason`) | Что значит | Что делать |
|---|---|---|
| `refresh_rejected` | Dodo IS отказал в продлении | выпустить новую ссылку входа для страны |
| `unauthorized` | ключ доступа не принят | подождать ночного продления; если не прошло — новая ссылка; проверить контур |
| `network` | Dodo IS не ответил или ответил ошибкой | подождать следующего часа; держится сутки — смотреть лог бота |
| `rate_limited` | Dodo IS ограничил частоту | ничего, повторится |
| `no_units` | в стране нет работающих пиццерий | проверить, что вход не чужой страны |
| `none_open` | вход ни одной пиццерии не открывает | новая ссылка от учётки с доступом |
| `write_failed` | пара ключей получена, но не записалась в базу; держится в памяти бота ровно до его перезапуска | не перезапускать бот, смотреть базу; если бот перезапущен — новая ссылка |
| `no_keys` | не заданы ключи приложения маркетплейса | вставить их в блоке вверху вкладки |
| `no_tokens` | ключи входа не нашлись или не открылись | проверить `SECRETS_KEY` и сделать новую ссылку |

Подробнее «симптом → куда смотреть → что делать» по всем загрузчикам — в [`38-runbook.md`](38-runbook.md).
