# Pointer API — внешний источник оценок и отзывов с карт

> Статус: работает с 09.10.2026 — бот раз в сутки грузит оценки филиалов на картах,
> страница «Рейтинги» показывает их блоком «Оценки на картах». Документация вычитана
> 16.09.2026, ответы сверены с живым API 09.10.2026.

## Как устроено у нас

- **Загрузка** — задача бота `src/bot/maps_loader.py`: раз в час смотрит журнал
  `maps.loads`; если удачной загрузки не было 20 часов, зовёт `src/ratings/maps.py:
  load_once`. Загрузка и шаг истории идут под замком базы (`src/db/job_lock.py`, F-125): второй
  процесс (перекрытие при выкатке, второй экземпляр) при занятом замке заход молча пропускает.
  Руками: `docker exec decimus-bot-1 python -m src.ratings.maps`.
- **Запросы** (`src/ratings/pointer.py`): `/networks`, затем `/companies?network_uuid=…
  &with_ratings=1` по каждой сети — около 25 запросов с паузой 1,1 с. Суточные экспорты
  не используются: оценки филиала приходят в обычном списке.
- **Хранение** (миграция `0044`, `src/db/maps_store.py`): `maps.companies` — филиалы
  (страна, город, адрес, координаты, сеть); `maps.ratings` — оценка на дату по ключу
  (филиал, карта, дата), так копится своя история; `maps.loads` — журнал загрузок.
  Выборки «последняя оценка на карте» (`latest`) и «оценка пиццерии на дату»
  (`unit_scores`) читают по одной записи на пару (филиал, карта) через `lateral ...
  limit 1` и индекс `ratings_provider_company_date_idx` (миграция `0055`), а не весь
  ряд: при 107 тыс. снимках это 4–6 и 1,5 мс вместо 130–170 мс.
- **Показ**: блок `maps` страницы «Рейтинги» (компоновка D368). Оценка страны на карте —
  средняя по всем отзывам: оценка филиала взвешена числом его отзывов; филиал без
  отзывов в среднее не входит. Показываются Google и Яндекс.
- **Swarm** получает те же оценки через API v1 — `GET /api/v1/maps/ratings` (D390,
  контракт — `docs/31-swarm-api.md`, раздел «API чтения для Swarm»): средние стран по
  той же формуле и оценки связанных пиццерий на дату с изменением к дате сравнения.
  Своим ключом Pointer Swarm не ходит: ключ один, у загрузчика Децимуса.
- **История и динамика**: `GET /companies/{uuid}/ratings?date_from&date_to` отдаёт оценки
  по дням, окно — не длиннее 31 дня, история — около года назад. Историю доливает сам бот (`src/bot/maps_loader.py`, #616): каждый час до 300
  запросов за круг (окна по 30 дней, 12 месяцев; ~47 минут на 212 филиалов, то есть
  около девяти кругов), закрытая история часа не тратит. Что уже легло, решает база
  (окно, где у филиала почти все дни, пропускается), поэтому выкатка, пересоздавшая
  контейнер, дозагрузку не обрывает: первый час после старта продолжает с места. Окно,
  которое не покрылось (филиал открылся позже), в тот же день заново не запрашивается.
  Руками тем же кодом: `docker exec decimus-bot-1 python -m src.ratings.maps history 12`
  (разом, без предела). Блок показывает оценку на конец
  выбранного периода и изменение к концу прошлого.
- **Оценки поштучно** (миграция `0127`, `src/ratings/maps_reviews.py`, D732–D733): карта в
  «Качестве» считается по `GET /reviews?company_uuids&provider_ids&published_at_from&published_at_to`
  (даты строго без времени, с временем — 400). В `maps.reviews` лежит id, звёзды, дата
  публикации и признак удаления; текст отзыва не храним. Историю за 12 месяцев и ежедневную
  догрузку двух последних месяцев ведёт тот же цикл бота под тем же замком, ход — в
  `maps.reviews_sync`. Оценка, исчезнувшая из свежей выгрузки окна, помечается удалённой.
  Набор карт — `pointer.MAP_PROVIDERS`. Сверка: `python -m src.ratings.maps reconcile` и строка в
  логе бота раз в сутки — оценок в выгрузке против прироста счётчика карточки за то же время.
- **Связь с пиццерией** (миграция `0045`, `src/ratings/maps_link.py`): кода нашей сети у
  Pointer нет, поэтому после каждой ночной загрузки филиал связывается с ближайшей
  пиццерией Dodo из публичного API (`publicapi.dodois.io/<страна>/api/v1/unitinfo/all`,
  `Type = 1`, поле `Location`): сразу — до 300 м; до 1,5 км — если следующая пиццерия
  хотя бы вдвое дальше (метка на карте бывает неточной, а пиццерии стоят минимум в
  нескольких кварталах друг от друга). Пиццерия достаётся ближайшему филиалу.
  Код пиццерии (`UUId`) — тот же, что `ratings.units.dodo_id`. Руками:
  `python -m src.ratings.maps link`. В списках Top/Bottom рядом с пиццерией —
  её оценка в Google на конец периода.
- **Не пиццерия** (миграция `0047`, D453): филиал с непустым
  `maps.companies.excluded_reason` в оценки стран и пиццерий не входит. Отметка
  ставится руками (`update maps.companies set excluded_reason = '…' where uuid = …`) и
  переживает ежедневную загрузку. Исключены: тестовая карточка в Кыргызстане и
  учебный центр в Беларуси.

## Что видит ключ (09.10.2026)

21 сеть Dodo — по стране, 212 филиалов. Код страны у филиала есть почти у всех (4 без
кода). Ответы списков лежат в `items`, а не в `data`; `meta.total` — для пагинации.

**Документация:** https://api.pntr.io/ (там же кнопка «Download OpenAPI specification»).
**База:** `https://api.pntr.io/v1`.

## Зачем нам

Будущий блок аналитики по странам на платформе: внешняя оценка пиццерии глазами гостя
(рейтинг и отзывы на картах) рядом с внутренней оценкой аудита. Гипотеза связи —
пиццерия ↔ филиал (`company`) Поинтера.

## Что это за сервис

Собирает оценки, отзывы и комментарии с картографических сервисов по сети точек,
позволяет отвечать на отзывы и вести переписку. Иерархия: **сеть (network)** → **филиал
(company)** → **отзыв (review)**.

## Доступ

- Схема `bearerAuthToken`: HTTP `Authorization: Bearer <TOKEN>` в каждом запросе.
- Ключ выдаёт поддержка Поинтера по заявке с названиями сетей и списком методов,
  которые планируем использовать. Самообслуживания нет — ключ надо запрашивать.
- **Rate limit: не более 1 запроса в секунду.** Это проектное ограничение, а не деталь:
  аналитика на лету по такому лимиту не строится, нужен свой кэш/ETL.
- **Ключ получен 09.10.2026.** Хранится зашифрованным в базе (ставится и меняется в «Администрировании» → «Ключи и API» → «Наши ключи к внешним сервисам», D576)
  или, пока там не задан, в окружении прода (`POINTER_API_KEY` в `.env` сервера); в репозиторий и чат не попадает.
- **Суточные лимиты (со слов поддержки, 09.10.2026):** `GET /export/json/companies/ratings`
  (рейтинги) и `GET /export/json/companies` (список филиалов) — не чаще одного раза в
  сутки. Значит, их зовёт только ночная загрузка, а повтор после сбоя ждёт следующих суток.
- **Молдовы и Венгрии у ключа нет:** Поинтер эти страны пока не поддерживает.

## Пагинация

Везде `limit` (по умолчанию 10, максимум 100) и `offset` (по умолчанию 0);
в ответе `meta: { total, limit, offset }`.

## Фильтры

`GET /companies`: `network_uuid`, `yandex_xml_ids`, `with_ratings`, `with_info`, `q`
(поиск по имени филиала), `limit`, `offset`.

`GET /reviews`: `network_uuids`, `company_uuids`, `provider_ids`, `has_reply`,
`is_reply_published`, `has_comment`, `rating` (список значений), `published_at_from/to`,
`created_at_from/to`, `reply_created_at_from/to`, `reply_published_at_from/to`,
`is_activator`, `is_changed`, `with_photos`, `with_tags`, `with_smart_tags`, `tag_ids`,
`smart_tag_ids`, `limit`, `offset`.

`GET /networks/{uuid}/competitors`: `locality_name` (фильтр по населённому пункту).

## Главное для аналитики по странам

**Фильтра по стране в API нет** — ни у филиалов, ни у отзывов. География есть только
как поля объекта филиала:

- `address_fields`: `country` (название строкой, напр. «Россия»), `area`, `city`,
  `street`, `building`, `postcode`, `address_notes[]`;
- `country_code` (напр. `RU`), `latitude`, `longitude`.

Отсюда порядок работы для странового среза: выгрузить филиалы (лучше через
`/export/json/companies`), сгруппировать у себя по `country_code`, и только потом тянуть
отзывы и рейтинги по `company_uuids`. То есть страновая агрегация — наша, а не их.
Для инкремента есть вебхуки, чтобы не опрашивать заново.

## Типовые сбои Pointer

Ответ API читается в `src/ratings/pointer.py` (`http_fetch`): любой код не 2xx становится `PointerError` с текстом
«Pointer ответил <код> на <путь>», сеть и таймаут — «Pointer недоступен (…)». Журнал загрузок — `maps.loads`, лог — контейнер бота.
Пошагово «что делать» — [`38-runbook.md`](38-runbook.md), раздел «Карты (Pointer)».

| Что видно | Причина | Что делать |
|---|---|---|
| «Pointer ответил 400», в теле «слишком много запросов» | превышен лимит **1 запрос в секунду**: два процесса или ручной запуск рядом с ночной загрузкой (код паузы между запросами — `REQUEST_GAP_SEC` = 1,1 с) | подождать; не запускать ручные `python -m src.ratings.maps` в час загрузки; проверка ключа на экране эту ошибку не считает отказом ключа (жёлтый, #1256) |
| «Pointer ответил 400» на запрос оценок или отзывов, лимит ни при чём | в датах `published_at_from/to` передано время: нужны даты строго без времени | искать в коде, откуда взялась дата с временем (`src/ratings/maps_reviews.py`); руками — только `YYYY-MM-DD` |
| «Pointer ответил 401» или 403 | ключ не принят: отозван, просрочен, вставлен с лишним пробелом | поставить новый ключ (ниже), на экране «Подключения» нажать «Проверить» у Pointer |
| Сверка оценок поштучно с счётчиком карточки показывает расхождение | в выгрузке окна оценок меньше или больше, чем прирост счётчика карточки: оценка удалена на карте, пришла позже окна, либо окно не догружено | расхождение только в логе бота (строка «Оценки карт поштучно…»), людям ничего не уходит; повторить сверку `python -m src.ratings.maps reconcile` после ночной загрузки; держится неделю — звать владельца |
| «Pointer недоступен», таймаут | сеть или сбой стороны Pointer | подождать следующего часа; загрузка повторяется сама |
| «больше N страниц — остановлено» | у ответа больше страниц, чем допускает предел защиты от зацикливания | сообщить владельцу: предел `MAX_PAGES` поднимает разработчик |
| В логе бота при старте «Оценки карт: POINTER_API_KEY не задан — загрузка выключена» | задача карт запускается, только если переменная `POINTER_API_KEY` есть в окружении бота (`src/bot/maps_loader.py`, проверка при старте); ключ, поставленный **только на экране**, задачу не включает, хотя сам ключ читается из базы первым. Выяснено по коду, на проде не проверялось | держать `POINTER_API_KEY` в `.env` сервера и перезапускать `bot` после правки; расхождение «экран против окружения» заведено задачей |

**Где вставляется ключ.** «Администрирование → Ключи и API → Наши ключи к внешним сервисам → Pointer» (хранится зашифрованным в базе, D576);
запасной путь — переменная `POINTER_API_KEY` в `.env` сервера (файл `.env` в каталоге проекта на VPS, права 600). Значение в репозиторий,
чат и документы не попадает. Ключ выдаёт поддержка Pointer по заявке; самообслуживания нет.

**Что уже выяснено** (раньше это были открытые вопросы): у Dodo сети Pointer заведены по странам (21 сеть, 212 филиалов на 09.10.2026);
филиал связывается с пиццерией по близости координат (`maps_link.py`, выше); поля отзыва сверены с живым API и разобраны в
`src/ratings/pointer.py`.
