# Pointer API — внешний источник оценок и отзывов с карт

> Статус: разведка, ключа доступа нет.
> Сверено с OpenAPI-спекой **22.09.2026**. Отдельного файла спеки по адресу нет
> (`/openapi.json`, `/swagger.json` — 404; `/v1/openapi.json` — 401). Спека вшита
> в страницу https://api.pntr.io/ как `__redoc_state`; факты ниже взяты из неё,
> а не из текста страницы и не по памяти.

**База:** `https://api.pntr.io/v1`. Всего в спеке 20 путей, 26 операций, 56 схем.

## Зачем нам

Внешняя оценка пиццерии глазами гостя (рейтинг и отзывы на картах) рядом с
внутренней оценкой аудита — чтобы видеть, сходятся ли они. Аудит говорит, как
пиццерия выглядит в день проверки; карты говорят, как её видят гости каждый день.
Расхождение между ними — сам по себе сигнал.

Иерархия Поинтера: **сеть (network)** → **филиал (company)** → **отзыв (review)**.
Гипотеза связи: наша пиццерия ↔ `company`.

## Доступ и лимиты

- `Authorization: Bearer <TOKEN>` в каждом запросе (схема `bearerAuthToken`).
- Ключ выдаёт поддержка Поинтера по заявке с названиями сетей и списком методов.
  Самообслуживания нет.
- **Rate limit: не более 1 запроса в секунду** (единственное ограничение, названное
  в описании API).
- Пагинация: `limit` (по умолчанию 10, максимум 100) и `offset`; в ответе
  `meta: { total, limit, offset }`.
- Отдельный потолок: `/export/json/companies/ratings` принимает не более
  **50** `company_uuids` за запрос.

## Целевой контур первой очереди

Балканы: **Сербия, Словения, Болгария, Хорватия, Черногория**. Дальше — остальные
страны присутствия по мере готовности.

Геосервисы в API ровно три (`GET /providers`): `1` — Яндекс Карты, `2` — Google
Карты, `3` — 2ГИС. Для выбранного региона реально работает **только Google
(`provider_id=2`)**: Яндекс и 2ГИС там либо не ведут карточки бизнеса, либо не
отдают статистику. Это надо подтвердить у поддержки до заявки на объём — от ответа
зависит, есть ли смысл в методах трафика (см. ниже) и не окажется ли половина
запрошенного пустой.

## Полный список операций и что мы берём

| Операция | Берём | Зачем / почему нет |
|---|---|---|
| `GET /providers` | **да** | справочник геосервисов, 1 запрос на всю жизнь интеграции |
| `GET /networks` | **да** | какие сети нам вообще доступны под ключом; `with_ratings` даёт рейтинг сети целиком |
| `GET /companies` | **да** | реестр филиалов: uuid, координаты, `country_code`, ссылки на карточки. С `with_ratings` и `with_info` |
| `GET /companies/{uuid}/ratings` | **да** | **динамика рейтинга точки**: `date_from`/`date_to`, в ответе ряд `ProviderRating` с полем `date` |
| `GET /reviews` | **да** | сами отзывы со всеми фильтрами (см. ниже) |
| `GET /export/json/companies` | **да** | разовая и периодическая выгрузка всех филиалов одним запросом; есть `bbox` |
| `GET /export/json/reviews` | **да** | массовая выгрузка отзывов плоскими записями, с `company_country` |
| `GET /export/json/companies/ratings` | **да** | срез рейтингов всех филиалов на дату, пачками по 50 uuid |
| `GET /networks/{uuid}/ratings` | **да** | агрегат по сети — контрольная сумма к нашей собственной агрегации |
| `GET /networks/{uuid}/tags` | **да** | словарь ручных тегов: без него `tag_ids` в отзывах — числа без смысла |
| `GET /networks/{uuid}/traffic/{provider_id}` | **да, если Google в регионе отдаёт** | воронка видимости карточки: показы, маршруты, звонки, переходы |
| `GET/POST/PUT/DELETE /webhooks` | **да, вторым шагом** | события `reviews`, `comments`, `messages` — инкремент вместо опроса |
| `GET /reviews/{id}/comments` | под вопросом | нужен, только если в Google-карточках региона комментарии к отзывам реально есть |
| `GET /networks/{uuid}/competitors` | **спросить цену** | платная опция «Карта конкурентов»: бенчмарк по городу. Фильтр — `locality_name` |
| `POST/PATCH/DELETE /reviews/{id}/reply` | нет | публикация ответов — не наша задача, доступ просим **только на чтение** |
| `PATCH /reviews/{id}/report` | нет | то же |
| `POST /reviews/{id}/comments` | нет | то же |
| `GET /conversations`, `GET/POST /conversations/{uuid}/messages` | нет | переписка с гостями ведётся не у нас |
| `POST /feedback-activator/review-email-requests` | нет | рассылка запросов отзыва — отдельный продукт, не аналитика |

Просим **только GET** (плюс управление своими вебхуками). Это и упрощает согласование,
и снимает риск: ключом нельзя ничего опубликовать от лица сети.

## Что забираем в своё хранилище

**Филиал (`Company`)** — `uuid`, `name`, `number`, `yandex_xml_id`, `full_address`,
`lat`/`lng`, `country_code`, `address_fields` (`country`, `area`, `city`, `street`,
`building`, `postcode`), `status_type_id` (открыт/закрыт/…), ссылки на карточки
(`google_maps_link`, `yandex_maps_link`, `twogis_maps_link`, `pointer_link`),
`working_times`, `phones`, `websites`, `added_at`, `updated_at`,
`weighted_mean_rating`, `ratings[]`.

**Рейтинг (`Rating`)** — `provider_id`, `avg_rating`, `ratings_count`, `date`.
Три величины, а не одна: средняя оценка, **число оценок** и дата среза. Рост числа
оценок при неизменной средней — отдельный сигнал.

**Отзыв (`Review`)** — `id`, `provider_id`, `company_uuid`, `network_uuid`, `rating`,
`text`, `author`, `published_at`, `created_at`, `updated_at`, `is_changed`,
`is_deleted`, `is_activator`, `provider_link`, `photos[]`, `reply`, и главное:
- `text_tonality` — тональность, посчитанная на их стороне (позитив / нейтрал / негатив);
- `tags[]` — ручные теги сети;
- `smart_tags[]` — **автоматические теги тем отзыва**. Это самое ценное для нас:
  темы гостевых жалоб ложатся на зоны чек-листа аудита, и сравнение «что нашёл
  аудитор» против «на что жалуются гости» получается без своей NLP-обработки.

**Плоская запись экспорта (`PlainReview`)** — то же короче, плюс `has_text`,
`has_reply`, `reply_text`, `reply_created_at`, `reply_published_at`,
`company_yandex_uuid`, `company_google_uuid`, **`company_country`**. Последние три
приходят только если перечислить их в `additional_fields` (enum: `text`, `reply_text`,
`company_yandex_uuid`, `company_google_uuid`, `company_country`).

**Трафик карточки (`/networks/{uuid}/traffic/{provider_id}`)** — `group_by` (день /
неделя / месяц), `company_uuids`, `date_from` (по умолчанию год назад), `date_to`.
Метрики различаются по геосервису; для Google: показы в Картах и Поиске отдельно для
десктопа и мобильных, `business_direction_requests_count` (построения маршрута),
`call_clicks_count`, `website_clicks_count`, `total_actions_count`. У Яндекса и 2ГИС
шире — там есть `review_views_count`, `photo_views_count`, `working_time_views_count`.

### Метрики, которые получаются даром из этих же полей

Их не надо просить — они считаются из уже забранного, но их стоит держать в виду,
раз уж мы описываем, зачем нам данные:

- **Доля отвеченных отзывов и время ответа** — из `has_reply`, `reply_created_at`,
  `published_at`. Это управляемая метрика работы управляющего, а не погода на рынке.
- **Скорость набора оценок** — производная `ratings_count` по датам.
- **Профиль негатива по темам** — `smart_tags` в срезе отзывов с `rating <= 3`.
- **Сходимость с аудитом** — оценка аудита против рейтинга карт на ту же дату.

## Как получить страновой срез

**Фильтра по стране в API нет** — ни у филиалов, ни у отзывов. Страна доступна тремя
путями, и все три — обходные:

1. поле филиала `country_code` / `address_fields.country` — группируем у себя после
   выгрузки филиалов (основной путь);
2. `GET /export/json/companies` принимает **`bbox`** — рамку WGS84 из четырёх
   координат. Балканы вырезаются одной рамкой, но рамка не равна границам стран:
   страну всё равно проверяем по `country_code`;
3. `company_country` в `additional_fields` экспорта отзывов — страна прямо в строке
   отзыва, удобно для проверки, что ничего не потеряли.

Порядок: выгрузить филиалы → отобрать по `country_code` (`RS`, `SI`, `BG`, `HR`, `ME`)
→ дальше тянуть отзывы и рейтинги по `company_uuids`.

## Нагрузка против лимита 1 запрос/с

Пусть `N` — число точек региона, `R` — всего отзывов по ним за историю.

| Заход | Запросов | При `N=80`, `R=40 000` |
|---|---|---|
| Реестр филиалов | 1 | 1 с |
| История отзывов, `limit=100` | `R/100` | ~400 запросов ≈ 7 мин |
| История рейтинга по точкам | `N` | 80 запросов ≈ 1,5 мин |
| Суточный инкремент отзывов | 1–2 | секунды |
| Суточный срез рейтингов, по 50 uuid | `N/50` → 2 | секунды |

Вывод: лимит 1 rps **не мешает** ни первой загрузке (первый проход — минуты, не часы),
ни суточному обновлению. Но аналитику он всё равно обязывает строить на своей копии
данных, а не на запросах в момент открытия экрана. `N=80` здесь — рабочая оценка числа
точек в пяти странах, её надо заменить фактом перед заявкой.

## Открытые вопросы у нас (до отправки заявки)

1. **Есть ли у Dodo действующий договор с Поинтером и по каким странам.** Если
   подключения по Балканам нет, разговор не про ключ, а про подключение сети.
2. **Фактическое число точек в пяти странах** — заменить оценку `N=80` в расчёте выше.
3. **Чем связывать `company` с нашей пиццерией.** В объекте филиала есть `uuid`,
   `yandex_xml_id`, `number`, `full_address`, координаты — нашего кода юнита не видно.
   Пока связь придётся строить по координатам и адресу с ручной сверкой, что плохо
   переживает переезды и переоткрытия точек.
4. **Куда складываем данные.** Выбор хранилища — за владельцем (см. CLAUDE.md), но
   решение нужно до первой загрузки: экспорт отзывов за историю — это не то, что
   держат в памяти процесса.
