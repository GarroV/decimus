# Сведения о пиццериях — «Свод пиццерий» девелопмента

> Ведётся руками. Решения: D374 (карточка пиццерии), D375 (почта партнёра),
> D376 (карточка страны).

## Что это

Справочник сведений о каждой пиццерии сети: статус, адрес, партнёр и его
почта, когда запустились ресторан и доставка, когда и почему закрылась,
площадь, посадочные места. Остальные колонки свода хранятся «на будущее» в
поле `extra`. Источник — Excel-файл «Свод пиццерий» отдела девелопмента.
Файл в репозиторий не кладётся: в нём личные данные партнёров. Он лежит вне
git (`workbench/private`) и попадает только в базу прода.

## Где видно

| Экран | Блок | Кто видит |
|---|---|---|
| Карточка пиццерии `/units/<id>` | «Сведения»: статус, адрес, партнёр, ресторан с, доставка с, закрытие, площадь, места | все, кому открыта карточка; **почта партнёра — только УК** |
| Страна `/country/<код>` | «Свод пиццерий»: все пиццерии страны по своду — работают, временно закрыты, открываются, закрыты; имя ведёт в карточку, если точка есть в справочнике | все, кому открыт экран страны |

## Как загрузить

```bash
# прод: скопировать файл в контейнер, загрузить, удалить копию
docker cp svod.xlsx <контейнер web>:/tmp/svod.xlsx
docker exec -w /app -e PYTHONPATH=/app <контейнер web> python -m src.ratings.svod /tmp/svod.xlsx
docker exec <контейнер web> rm /tmp/svod.xlsx
```

Загрузка заменяет справочник целиком: свод — полный список.

## Как устроено

- **Листы.** «Детальный свод» — действующие и строящиеся пиццерии, «закрытые» —
  закрытые. Действующая строка главнее закрытой с тем же именем: имя
  переехавшей пиццерии живёт дальше.
- **Стадия** (`stage`): `open` (ресторан или доставка открыты), `paused`
  (временно закрыта), `pipeline` (поиск помещения, проектирование, стройка),
  `closed` (лист «закрытые»). Статус свода хранится дословно рядом.
- **Даты.**
  - Запуск ресторана и доставки — первая выручка по ним в Dodo IS
    (колонки «дата поступления выручки по …»).
  - На листе закрытых — «Открытие ресторана» и «Открытие доставки».
- **Код.** В своде нет кода пиццерии, поэтому строка опознаётся по стране и
  имени. Сравнение идёт без регистра, пробелов и диакритики: «İzmir-1» —
  это «Izmir-1».
  - Код Dodo (`dodo_id`, тот же, что в рейтингах и на картах) загрузка
    подбирает по имени из публичного API Dodo. Если имя неоднозначно, код не
    ставится.
  - Точке справочника `units` тот же код ложится в `units.code` — по имени
    или синониму в пределах её страны. Через него карточка находит свою
    строку.
- **Отбрасывается:**
  - строка без имени, страны или статуса;
  - страна, которой нет в словаре `COUNTRIES` в `src/ratings/svod.py`;
  - колонки с именами сотрудников.

## Сверка справочника `units` с эталоном (#316, #909)

Свод — эталон: у каждой пиццерии в нём имя с номером, адрес и код Dodo. Точки
`units` заведены разными путями (с сайтов стран, руками на кириллице, по факту
проверки) и с ним не связаны: «Bishkek — 7 Manas Ave» и «Bishkek-8» — одна
пиццерия, «Тбилиси-1» и «Tbilisi-1» — тоже. `make units-normalize` связывает их:

```bash
make units-normalize                                       # сухой прогон по базе, ничего не пишет
make units-normalize ARGS="--from-dir выгрузка/"           # то же по выгрузке CSV, без базы
make units-normalize ARGS="--apply --backup копия.json"    # записать одной транзакцией
```

Правила сопоставления идут по убыванию доверия, первое давшее кандидатов решает
(`src/domain/unit_match.py`): код = `dodo_id`; то же имя; синоним; «Город-N» на другом
алфавите; адрес (улица и номер дома в той же стране — высокое доверие, одна улица
или район без номера — среднее); имя-город, в котором в своде одна пиццерия.
Несколько кандидатов — точка не трогается и печатается с кандидатами; не нашлось —
печатается, не трогается. `--min-confidence high` оставляет только высокое.

Что запись делает с найденной точкой:

- **Переименование** в имя эталона, `units.code` = `dodo_id`, город и страна — если не
  были заданы; прежнее имя остаётся синонимом (бот и поиск находят точку по-старому,
  история остаётся при ней). Страну база может не пустить (триггер `units_space_frozen`,
  если у точки есть проверки): тогда остальное записано, а отказ напечатан.
- **Слияние пустого дубля**: две точки на одну строку эталона — остаётся та, у которой
  код эталона, затем та, на которую больше ссылок; синонимы и имя дубля переходят
  оставшейся, дубль удаляется. Дубль, на который ссылаются проверки, история переносов
  (`inspection_moves` — только на добавление), предписания, поездки или рейтинги, **не
  сливается**: удаление стёрло бы или переписало историю. Он печатается как
  «заблокирован» — решение за человеком. Слияние удаляет строки `units`, чего роли
  приложения не выдано, поэтому запись идёт под `DATABASE_ADMIN_URL`.

Повторный запуск ничего не меняет. Перед записью снимок затронутых строк `units` и
`unit_aliases` ложится в файл `--backup`.

Чтобы расхождение не вернулось, загрузка с сайтов (`make units ARGS="sites"`) сверяет
каждую точку с эталоном страны: известную эталону заводит под его именем и кодом (имя
сайта — синонимом), а точку, чьё имя или синоним уже есть в справочнике, не дублирует.
Заведение руками и мастер бота по-прежнему идут через `canonical_unit` (D233) и под
эталон не подстраиваются.
