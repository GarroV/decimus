# Обучение пиццерий (iSpring)

> Статус: первая версия (#906, D574, D575, D578). Загрузка раз в сутки из iSpring Learn,
> экран «Обучение» читает нашу базу. Рукописный документ.

## Что это

Экран отвечает на один вопрос: **насколько обучены люди в пиццерии, стране и сети — и где
хуже всего.** Данные о прохождении курсов лежат в LMS iSpring; раз в сутки бот забирает их,
сворачивает в **счётчики по пиццерии** и кладёт в нашу базу (D574). Экран читает базу, а не
iSpring.

**Данных о сотрудниках у нас нет и не будет (D575).** Ни идентификаторов, ни имён, ни почты,
ни `STAFF_ID`, ни строк «человек × курс»: результаты читаются по пиццерии в память, считаются
и забываются; в базу и в лог идут только числа и названия подразделений и курсов.

## Поверхности

| Поверхность | Что показывает | Кто видит | Чем питается |
|---|---|---|---|
| Экран «Обучение» (`/training`, группа «Статистика», рядом с «Рейтингами», D578) | Слева «Все страны» и страны с обученностью, выбранная страна раскрывается пиццериями; справа плитки, список худших сверху, курсы, не сопоставленные пиццерии | Все роли, кроме контроля (D420: контроль ведёт только «Рейтинги»); `view.training`; партнёр — только свои страны, чужая страна в адресе — 404 | `src/db/training_read.py` → снимок последней загрузки |
| Суточная загрузка | Забирает подразделения и результаты, кладёт снимок дня, пишет журнал | Никому: служебная задача бота | `src/bot/learning_loader.py` → `src/learning/sync.py` |
| Ручной запуск | То же один раз; печатает только числа | Админ площадки | `python -m src.learning` |

## Сквозные сценарии

1. **Первый запуск.** Главный админ ставит ключи iSpring на «Администрирование → Ключи и API»
   (блок «Наши ключи к внешним сервисам», D576, D650). До первой загрузки экран честно пуст: «Данные из iSpring ещё не
   загружены»; главному админу под текстом ссылка на «Ключи и API», остальным — «ключи ставит
   главный администратор». Ключей нет — загрузчик молчит и ждёт, в лог идёт одна строка.
2. **Ежедневно.** Раз в час бот смотрит журнал `learning.loads`; если удачной загрузки не было
   20 часов — грузит. Один процесс на заход (замок базы). Сбой — запись в журнал и одна тревога
   владельцу в канал FURCA (как у агрегаторов, D438), повторные попытки каждый час молчат до успеха.
3. **Смотреть.** «Все страны» → страна → пиццерия: плитки пересчитываются по выбранному, ниже
   список худших и курсы. Не сопоставленные с рейтингами пиццерии видны отдельным блоком и
   открываются так же.

## Определения (единственное место; в коде — `src/domain/training_metrics.py`)

Одна строка результата iSpring — **одно назначение** курса человеку. Считаются только
активные сотрудники (`userStatuses[]=1`).

| Показатель | Определение |
|---|---|
| Назначено | все строки |
| Завершено | статусы `complete`, `passed`, `attended` |
| Обученность % | завершено / назначено |
| Просрочено | `isOverdue` и не завершено |
| Полностью обучены % | сотрудники, у которых завершено всё назначенное, / сотрудники; считается в памяти, хранятся два числа (`people_total`, `people_trained`) |
| Сдали тест % | `passed` / (`passed` + `failed`) |
| Среднее время на курс | по завершённым, у которых `timeSpent` > 0 (ноль — «нет данных») |
| Средний балл | по строкам с `awardedScore` (в базе, на экран пока не выведен) |
| Дни до завершения | по завершённым с обеими датами, не меньше нуля (в базе, на экран пока не выведен) |

`in_progress`, `not_started` и `failed` считаются отдельно (в базе, на экране пока не нужны);
остальные статусы (`incomplete`, `no_result`, `pending`, `declined` и др.) входят только в
«назначено» — из знаменателя не пропадают, завершёнными не считаются. **Проценты считаются из сумм**, а не как среднее
процентов: страна и сеть — сумма счётчиков пиццерий (`Counters.__add__`). В страну и сеть идут
**только сопоставленные** пиццерии, офисы не входят.

## Данные из iSpring

- Хост `https://api-learn.ispring.com`; токен `POST /api/v3/token` (`client_credentials`,
  живёт 30 минут, обновляется сам); ответы просим как JSON (`Accept`).
- `GET /departments` — дерево: `Dodo Brands` → `Dodo Pizza` → страна `Dodo Pizza - Romania` →
  подразделение пиццерии `Brasov-1: Brasov - Dodo Pizza` (иногда без `: …`). Первая версия —
  только ветка `Dodo Pizza`. Пиццерия — название с номером точки до `:`; остальное на этом
  уровне — офис. Страна, которой нет в справочнике сети, но есть в iSpring (Молдова), берётся
  из короткого списка в `src/learning/departments.py`.
- `GET /learners/results?departmentIds=<id>&userStatuses[]=1` — по каждой пиццерии, потому что
  фильтр по подразделению **не включает вложенные**. Параметр обязан называться со скобками:
  `userStatuses=1` iSpring отвечает 500 (проверено 20.10.2026). Страницы по 1000, `pageToken`.
- Названия курсов берутся из тех же результатов (`courseTitle`).
- Вежливо: запросы по одному, таймаут 30 с, `429`/`5xx` повторяются с нарастающей паузой (до 4
  попыток). Сбой на любой пиццерии роняет заход целиком — снимок, где половина пиццерий пустая,
  выглядел бы как «обученность упала»; прежний снимок остаётся.

Сопоставление с пиццерией рейтингов — по короткой части названия и стране
(`src/ratings/matching.py`). Не сопоставленная остаётся пиццерией с пустой связью
(`unit_dodo_id`) и выходит на экран отдельным блоком «Не сопоставлены».

## Хранение (миграция `0085`, схема `learning`)

| Таблица | Что лежит |
|---|---|
| `learning.departments` | подразделение iSpring: код, название, вид (`country`/`pizzeria`/`office`), страна, связь с пиццерией рейтингов |
| `learning.courses` | код и название курса |
| `learning.unit_totals` | на дату загрузки и пиццерию — счётчики (`Counters`) |
| `learning.unit_courses` | то же по курсам (без «людей»: по курсу это назначения) |
| `learning.loads` | журнал загрузок: когда, исход, сколько подразделений и строк, текст сбоя без ключей и данных |

Снимок дня заменяется целиком; история копится по датам. Колонок про людей нет, и
`tests/test_db_learning_schema.py` падает на любой новой текстовой колонке сверх названий.

## Экран

Каркас — общий шаблон «выбор слева — рабочая область справа» (D474, `templates/_pick_page.html`),
как у «Стран»; шаблон `templates/training/index.html`, стили `static/decimus-training.css`,
подмена колонки без перескока — `country.js`. Состояние в адресе: `/training` — сеть,
`/training/<код страны>` — страна, `?unit=<подразделение iSpring>` — пиццерия.

Справа: плитки (обученность, полностью обучены, просрочено, среднее время на курс, сдали
тест); список стран (для сети) или пиццерий (для страны), хуже всего сверху, с полосой;
курсы по числу назначений (до 50); блок «Не сопоставлены» у сети и страны.

**Период.** Первая версия показывает одно состояние — снимок последней загрузки («Данные на
<дата>»). Календарь «с — по» (`_period.html`) не нужен, пока история в базе не накопилась;
когда накопится, период станет одним на экран и плитки получат движение к прошлому периоду.

## Глоссарий

| Термин | Значение |
|---|---|
| Подразделение | узел дерева iSpring: страна, пиццерия или офис |
| Назначение | одна строка результата: курс, назначенный человеку |
| Снимок | счётчики подразделений на дату загрузки |
| Сопоставлена | пиццерия iSpring нашлась среди пиццерий рейтингов |
