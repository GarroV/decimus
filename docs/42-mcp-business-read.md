# Бизнес-данные через MCP

Администраторы управляющей компании и партнёров читают данные через существующее
MCP-подключение. Повторное подключение не требуется; клиенту может потребоваться
обновить список инструментов. Права берутся из авторизации. Партнёр получает
только страны своего пространства; параметра для подмены пространства нет.

| Данные | Инструмент |
|---|---|
| Продажи, заказы, средний чек, зал/самовывоз/доставка, источники заказов | `sales_summary` |
| Месячное «Качество»: РС/РКО, клиентские оценки, Google/Яндекс, агрегаторы, доли, веса и итог | `quality_summary` |
| РС/РКО: сводка, пиццерии, периоды конкретной пиццерии | `ratings_summary`, `ratings_units`, `ratings_unit_periods` |
| Состояние сбора агрегаторов | `aggregators_status` |
| Проверки, содержание, история пиццерии и нарушения | `list_inspections`, `get_inspection`, `unit_history`, `findings_by_unit`, `network_summary` |

Новые инструменты только читают существующий кэш. Они не запускают сбор,
не обращаются к Dodo IS при каждом вопросе и не создают записи проверок.
Расчёты «Качества» общие для сайта и MCP: `src/ratings/quality_data.py`;
группировка продаж — `src/ratings/sales.py`.

## Параметры новых инструментов

`month`: `YYYY-MM`, по умолчанию текущий месяц. `country`: код страны.
`unit`: точный код пиццерии или часть названия. Поиск по пиццерии применяется
также к итогам страны. `limit`: 1–200, по умолчанию 50; `offset`: смещение.
`next_offset = null` означает последнюю страницу. Итоги стран относятся ко
всей отфильтрованной выборке, независимо от страницы пиццерий.

Например, `sales_summary(month="2026-10", country="RS", limit=50)` и
`quality_summary(month="2026-10", country="AM", unit="Ереван")`.

Оба ответа включают предыдущий месяц и тот же месяц прошлого года.
Сравнение календарное, без поправки LFL. Для незавершённого текущего месяца
процентное изменение продаж не выводится: базы сравнения полные.

Деньги возвращаются десятичными строками с валютой отдельно по каждой стране;
общей денежной суммы разных стран нет. Смешанные валюты внутри одной страны
в `sales_summary` дают явный отказ. Средний чек — выручка / заказы, для которых
получена выручка (`orders_with_revenue`). Отдельно полученные заказы агрегаторов
могут дополнять `orders`; без выручки они не меняют знаменатель среднего чека.
`null` означает отсутствие данных, ноль — полученный ноль.

РС/РКО: шкала 0–100. Клиентские оценки, карты, приведённые оценки агрегаторов
и итог «Качества»: 0–5; исходная шкала агрегатора также присутствует. Доли: 0–1.
Для перенесённых оценок карт указан месяц-источник. Проверки decimus читаются
отдельными инструментами; `quality_summary` их не подгружает.

## Проверка после обновления

С внешней машины, с действующим токеном администратора:

```bash
DECIMUS_MCP_URL=<публичный MCP URL> DECIMUS_MCP_TOKEN=<токен> \
MCP_SMOKE_COUNTRY=RS MCP_SMOKE_MONTH=2026-10 python -m tools.mcp_business_smoke
```

Проверка только читает: список инструментов, продажи/«Качество» за месяц,
существующие рейтинги и список проверок. Для партнёра на стенде дополнительно
задать `MCP_SMOKE_FORBIDDEN_COUNTRY` страны вне его охвата. Токены и ответы
с бизнес-данными в вывод не попадают. Пустой месяц не проходит этот смоук:
выбирать месяц и страну с собранными данными.

Если инструмент не появился — обновить список инструментов в MCP-клиенте,
проверить версию контейнера `mcp`. При `no_data` проверить месяц, охват и
свежесть загрузки на странице «Качество»; при отказе базы проверить её
доступность. Недоступная база не трактуется как отсутствие продаж.
