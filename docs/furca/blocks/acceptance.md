# Блок acceptance — этап приёмки проверки (D199) и правка записи на приёмке (D200)

Состояние, не хроника (≤120 строк). Хроника — `git log feat/acceptance-v2`.

## Что пользователь может сделать

Админ пространства открывает в реестре блок «Ждут приёмки», вычитывает
проверку по всему чек-листу её версии, исправляет ошибочную запись (пункт,
класс, зону, формулировку) с пересчётом оценки движком и подтверждает
проверку — только после этого она входит в историю сети. УК видит ждущие
партнёра на чтение.

## Контракт для исполнителя: починка наборов после переноса (выполнен)

Слив теперь оставляет проверку `draft`; чтение истории (`list_inspections`,
`get_inspection` без `include_on_review`, `findings_by_unit`, сводки обзора,
MCP) видит только принятые. Тест, который сливает проверку и затем читает
историю или полагается на заморозку принятой, обязан подтвердить её:
`accept_pushed(ident)` (или `accept_pushed()` — все ждущие) из
`tests/db_harness.py` сразу после `push_inspection`. Нужна фикстура `db_env`
(она выставляет `DATABASE_URL`). Утверждения тестов не ослаблять и не
удалять; продуктовый код не трогать. Образец правок — ветка
`origin/feat/revise-before-acceptance` (там `accept_pushed(db_env, ident)` —
у нас сигнатура `accept_pushed(*ids, dsn=None)`).
