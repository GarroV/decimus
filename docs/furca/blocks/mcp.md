# Блок: mcp

## Назначение

Работа через Claude с накопленными проверками (история точки, повторяющиеся нарушения, сводка по сети) и с самой методикой — чек-листом, по которому эти проверки считаются (D049). Форма взята с работающего `swarm-mcp`: JSON-RPC по HTTP, личный токен, мост stdio↔HTTP (D055).

Содержимое проверки обхода не пишет ни один инструмент. Мест, где блок перестаёт быть только чтением, три, все включаются отдельной настройкой и по умолчанию выключены целиком: правка методики (D049), снятие проверки из истории (D086/D089) — пометка на выданном документе, без единого знака правки внутри него, — и загрузка исторических проверок из старых отчётов (D305–D310): черновик с происхождением `import`, записи в который вносит и оценку которого считает движок, а подтверждает сам загрузивший. Проверок обхода эти инструменты не касаются (замок и обработчик требуют `origin = 'import'`).

## API-контракт

Пятьдесят один инструмент (источник истины — `src/mcp/catalogue.py: TOOLS`): шесть о проверках (`inspections`), один о снятии (`retraction`), два об исходнике эталона (`checklist_source`, открыты всякому токену), тридцать три о методике, карте кадров, маршруте и карте синонимов (`checklist`), девять о загрузке исторических проверок (`import`, право `MCP_IMPORT_TENANTS`). **Аргумента `tenant` нет ни у одного:** код арендатора приходит из токена и ниоткуда больше. У инструментов методики нет и аргумента `store`: хранилище версий подставляет точка входа.

**Форма ответа.** JSON внутри текстового блока MCP, ключи английские: это машинная поверхность, агент пересказывает её человеку сам. У каждой выдачи есть `status` словами — «ничего не найдено» отличимо от «не смогли прочитать», а `truncated` говорит, что чтение упёрлось в предел. `chat_id` наружу не отдаётся.

## Откуда берётся арендатор

**Из токена.** Связка `MCP_TOKENS=арендатор=токен,...` разбирается на старте; запрос приносит токен в `Authorization`, сервер переводит его в код арендатора и передаёт инструментам сам. Аргумент `tenant` в вызове получает явный отказ, а не отбрасывается тихо (T110). Один токен у двух арендаторов — отказ на старте; несколько токенов у одного — законно (по человеку на токен); токен короче 24 знаков — отказ; в `repr`, в текст отказа и в лог токен не попадает; сверка идёт `secrets.compare_digest`. Вторая дверь (T253, D098/D099) — личный токен, который выпускает бот и хранит отпечатком в базе; права на снятие проверки он не даёт.

**Подпись действия (D308).** Кроме арендатора токен даёт подпись `Access.actor`: `mcp:tg:<telegram_id>` для личного токена, `mcp:<арендатор>` для токена из `MCP_TOKENS`. Ею подписано подтверждение загруженной проверки (`accepted_by`); из аргументов вызова подпись не берётся.

**Право загрузки (D305, D335).** `MCP_IMPORT_TENANTS=HQ` — единственное допустимое значение: любое другое пространство (после `canonical_tenant`) — отказ на старте (`config._parse_import`), партнёрам загрузка задним числом не открывается. Пусто — загрузка закрыта (выключатель). Требует `MCP_CHECKLIST_STORE` и `AUDIT_DATA_DIR` (режим `current` берёт оттуда действующую версию эталона), иначе отказ на старте. Без права вызов отказывает до обработчика (`rpc.IMPORT_CLOSED`). Подтверждению нужна `DATABASE_RETRACTION_URL` (роль администратора истории), кадрам — `S3_*`; без них соответствующий инструмент отвечает отказом, остальные работают. Режимы и разбор их аргументов — `src/mcp/import_modes.py`. Пределы (строка base64 кадра, записи и кадры черновика, число черновиков, длины полей) — именованные константы в `src/mcp/imports.py`, `src/db/imports.py` и `src/mcp/import_modes.py`.

**Пространства (волна 1, #340).** Чтение проверок — по охвату тенанта токена
(`src/db/reach.py:reach_of`): УК — вся сеть, партнёр — пиццерии своих стран,
кто бы их ни проверял (D289). Снятие — только своего (`own_reach`). Методика
правится в пространстве токена (`checklist_layout.space_of`); эталон УК
партнёру — только чтение; правящий инструмент без `checklist` в пространстве
партнёра — отказ `NAME_THE_CHECKLIST`, а не молчаливая правка чек-листа УК.
Перечень чек-листов сужен до `read_spaces(tenant)`. Токен, выпущенный ботом,
открывает пространство того, кто его выпустил.

## Правила, которые здесь дороже удобства

- **Правка не переписывает действующую методику:** каждый вызов кладёт НОВУЮ версию рядом, публикация — отдельный вызов (D049, D050). Отклонённая правка приходит отказом словами движка, а не «готово, но»; отказы самого хранилища (пустая правка, занятое имя) ложатся в журнал наравне с отказами движка (T238).
- **Правила методики живут в движке, и здесь их не пересказывают.** Исключение ровно одно и не исключение вовсе: файлы, которых движок не читает, — карта кадров (`photo-cues.md`) и маршрут (`route.csv`). Про них `manage.py validate` не знает, поэтому коды сверяет сам блок, а записанное перечитывает разбором ПРОДУКТА (`src.recognize.cues`, `src.domain.route`), а не своим: свой разборщик означал бы, что блок согласен сам с собой, а на точке видно другое.
- **Сущности связываются кодами.** Переименование зоны не трогает код; маршрут и карта кадров уходят в файл в написании справочника, а не в том, как код набрали в вызове.
- **Оценка не считается заново** — держится контрактом `lint-imports`: `src.mcp` не импортирует движок.
- **Абсолютных путей в ответе нет** ни в успехе, ни в отказе (T120): путь печатается в лог процесса, агенту достаётся имя переменной окружения и то, что с ней не так.
- **Новый вид инструмента объявляется в ПЯТИ местах** (проверено на T294, T315, T313, T317): `src/mcp/catalogue.py`; `src/mcp/rpc.py` — только если вид новый; `tests/test_mcp_catalogue.py` — счётчик и имена по видам; `tests/test_mcp_server.py` — перечень имён и требование, чтобы обработчик вида лежал в названном модуле; `tests/test_mcp_no_paths.py` — обе таблицы аргументов, где годные обязаны доводить до успешного ответа, а негодные до отказа. Пропущенное место видно только прогоном тестов MCP.

## Definition of Done блока

- [x] Инструменты чтения отвечают на боевых данных, ответы сверены с прямым запросом к базе.
- [x] Доступ закрыт токеном; без него сервер не отдаёт ничего, включая перечень инструментов.
- [x] «Пусто» и «не смогли прочитать» — разные ответы, сказанные словами.
- [x] Ни один инструмент не считает оценку заново (контракт `lint-imports` и сверка с `domain.score()`).
- [x] Правка методики идёт новой версией, проходит проверку движком и попадает в журнал (T098).
- [x] Снятие проверки закрыто личным правом токена, подтверждается точкой и датой, чужого текста наружу не выпускает (T211).
- [x] Издание проверки опознаётся отпечатком, а не именем (T236); нелатинское имя набора читается всеми поверхностями блока (T243); письмо не молчит о находке без формулировки (T237).
- [x] Карта кадров правится через агента, колонки узнаются по заголовку (T144, T289); карта синонимов видна управляющей компании и правится ею (T294).
- [x] Партнёр читает исходник эталона, и это право отдельно от правки — разными хранилищами, а не флагом (T315).
- [x] Зона не только заводится, но и настраивается: доли набором и переименование (T313).
- [x] Порядок обхода точки задаётся из разговора, коды сверяет блок, пометки человека переживают правку (T317).
- [x] Историческая проверка загружается поштучно: записи проверяет и оценку считает движок по версии черновика, сверка с оценкой старого отчёта видна до подтверждения, подтверждение не открывает запрос экшн-плана; проверок обхода инструменты загрузки не касаются (D305–D310, миграция `0038`).

## Открытые вопросы к владельцу

- **Партнёрские наборы методики.** Методика одна на всю сеть, правка не разделена по арендаторам. `docs/02-domain.md` обещает, что «у партнёров со временем появятся свои наборы»; тогда хранилищу понадобится измерение арендатора, а инструментам — понимание, чей набор они правят. Сейчас этого нет намеренно.
- **Право инструментов ставить строке карты кадров зону** — поднято блоком `binding`.
- **Q057: нужен ли партнёру `route.csv` и рабочие колонки УК в исходнике эталона.** Сегодня в исходник уходит эталон (пункты, зоны с долями, классы, сроки, критерии), маршрут обхода — нет. За владельца не решено, инструменты чтения партнёром не тронуты.
