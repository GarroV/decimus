# Блок: web

## Назначение

Веб-админка управляющей компании: то, что сегодня доступно только через бота и
MCP, получает экран. Объём спринта — **базовая часть веб-версии** (D133), а не
вся она: каркас с честными заглушками (D138) и раздел «Проверки».

Раскладка берётся из прототипа владельца (`Бриф системы аудитов Decimus 2/
Dodo Audit Prototype v2.dc.html`, 9 разделов навигации), стиль — из
дизайн-системы линейки `GarroV/forma` (`dodo/core/dodo-ds.css` +
`dodo/decimus/domain.css`). Палитра `#5B57F2` и пара Space Grotesk / Manrope из
прототипа в продукт **не переносятся** (D136). Копия `dodo-ds.css` в папке
эталона разошлась с каноном — сверять с `forma`.

## API-контракт

Блок **ничего не считает сам**. Оценка, буква, разбивка по зонам, сроки —
только через уже существующие двери:

| Что нужно экрану | Чем берётся | Запрет |
|---|---|---|
| История проверок, карточка проверки | `src/db/queries.py` | свой SQL поверх тех же таблиц |
| Снятие проверки | `src/db/retract.py` (D086/D089) | второе понятие «удаление» |
| Состав методики, зоны, классы | `src/domain` | чтение `data/*.csv` напрямую |
| Правка методики (позже, T320) | те же двери, что MCP/CLI (D049, D050) | вторая копия правил версионирования |

Веб — **читатель**, а не второй владелец правды. Схему данных этот блок в
первой волне не меняет.

### Признак «построен / не построен»

Единственный источник — **данные** (реестр разделов в коде блока), а не
разметка на каждом экране: иначе он разойдётся с фактом молча (D138). Раздел с
признаком «не построен» получает ленту в навигации и явный экран «ещё в
разработке» при входе, а не пустую или декоративную страницу.

В объём **не входят и показываются непостроенными** (D139): «Календарь»,
«Назначить проверку», планирование как сущность.

## Зависимости

`db` (история проверок, снятие), `domain` (методика, зоны), `mcp` (границы
арендатора и прав — переиспользовать, не дублировать).

## Рамка стека

Задаётся диспетчером, конкретный фреймворк выбирает блок с обоснованием и
записывает в отчёт (D148):

- Python, тот же образ и `docker-compose.yml`, что у бота и MCP;
- **серверный рендеринг**, без сборщика и без Node в образе: дизайн приходит
  готовым CSS из `forma`, а не React-компонентами;
- синхронный код — как весь остальной продукт (`psycopg`, `openai`);
- статика дизайн-системы кладётся копией с указанием версии-источника, чтобы
  расхождение с `forma` было видно.

## Definition of Done блока

- [x] Раздел «Проверки» открывается в браузере и показывает проведённые
      проверки: список, карточка, снятие — на данных, а не на заглушках.
- [x] Все 9 разделов прототипа есть в навигации; непостроенные помечены лентой
      и дают экран «ещё в разработке» (D138).
- [x] Ни один процент и ни одна буква не посчитаны в этом блоке заново.
- [x] Язык интерфейса — параметр, а не константа (требование `CLAUDE.md`);
      тексты заведены на обоих языках (`product-i18n`).
- [x] Проверено живым запуском в браузере, а не только тестами.
- [~] Гейты проекта: формат, линт, типы, мёртвый код, границы модулей — зелёные.
      Полный `make check` в этой копии неполон: строк подключения к базе в ней
      нет намеренно, и тесты блоков `db`/`mcp` пропускаются. Гонит его
      диспетчер на приёмке. Новый пакет `src/web` внесён в контракты
      `import-linter` слоем над `db`/`domain`.
- [x] `docs/` пополнены: `docs/12-web-admin.md`, ссылка в `README.md`,
      переменные — в образце окружения.
- [x] **Вход (T323):** ни один маршрут админки не открывается без опознания;
      выход прекращает сессию на стороне сервера; учётки заводит команда
      проекта; тексты входа на ru и en; границы арендатора не ослаблены.

## Состояние блока

**Где стоим.** T318 (каркас), T319 (раздел «Проверки») и T323 (вход) сделаны и
проверены живым стендом. Стек внутри рамки D148: Flask 3.1.3 + Jinja +
waitress 3.0.2, серверный рендеринг, без Node.

**Как устроен вход** (T323, D155). Заслон — один `before_request`, а не
декоратор на маршруте: новый экран закрыт с минуты появления. Открыты ровно
два endpoint'а, перечисленные в `auth.OPEN_ENDPOINTS`. Кука подписана
(`itsdangerous`, ключ — `WEB_SECRET_KEY`; не задан — делается на запуск, и
админка говорит об этом строкой), а сессия живёт в базе: без записи на сервере
выход не прекращал бы доступ по снятой копии куки. `Secure` ставится по
факту HTTPS (в том числе `X-Forwarded-Proto` — TLS снимает туннель, D100).
Учётки и сессии — миграция `0014`: роль приложения на `web_users` имеет только
`select`, заведение и отключение идут ролью владельца схемы
(`DATABASE_ADMIN_URL`) через `make web-user`; четвёртой роли не заведено.
Пароль — scrypt с солью, сессия — отпечаток SHA-256, формы держат ограничения
схемы. Закрытие сессии одностороннее (сужающая политика). Заслон происхождения
переехал в `src/web/origin.py` и общий у снятия, входа и выхода.

**Чем проверено.** 108 тестов блока и его двери (`tests/test_web_*.py`,
`tests/test_db_web_access.py`), все зелёные; 17 проверок порчей — каждая
покраснела с внятной причиной (перечень и прогон —
`scratchpad/web-auth/porcha.py`). Живой стенд: своя база
(`docker compose -p decimus-web-auth`, порт 18301), схема накачена НА ПУСТУЮ
базу с нуля (все 14 миграций), три демо-проверки, сервер на 18300. Пройдено
настоящим браузером: закрытая страница → форма входа, неверный пароль → отказ,
верный → реестр с тремя проверками, карточка, выход щелчком → снова форма.
Отдельно доказано на живом стенде: копия куки, снятая ДО выхода, после выхода
не работает (200 → 302); `GET /logout` — 405; права роли приложения на
`web_users` — только `SELECT`; в базе лежит `scrypt$16384$8$1$…`.
`make fmt/lint/types/dead/bounds` — зелёные.

**Что дальше.** Публикация наружу (T324) — не в этом блоке: туннель и
переключатели на стороне владельца. Следующие разделы снимают ленту в
`src/web/sections.py` — приложение не соберётся, пока у раздела нет экрана.

**Разбор безопасности на приёмке** (агент, который блок не строил) принял заслон происхождения и границу арендатора: перебор идентификатора не даёт ни прочитать, ни снять чужую проверку — фильтр стоит в SQL, а «нет такой» и «не ваша» отвечают одинаково. Инъекций (Jinja, SQL, путь к статике) не нашлось. Две находки починены диспетчером до приёмки: запрет встраивания в чужой документ (`X-Frame-Options`, `frame-ancestors`) и текст отказа снятия — он выносил адрес базы на карточку, у которой входа нет.

**Что открыто (владельцу, не решаю сам).**

1. Сверка с эталоном нашла отсутствующее, чего нет в задачах блока:
   переключатель «внутреннее / как видит партнёр», выгрузка PDF с карточки,
   панель фильтров реестра. Не строил — это за границей T318/T319.
2. Терминология: `kind` в интерфейсе назван «Вид» / «Kind», а владелец в
   прототипе говорит «тип проверки». Слово не менял — оно связано с кодом.
3. Ролей у учёток нет: все вошедшие равны и видят одно и то же, включая
   снятие проверки. Это объём задачи (круг узкий), но как только в круг
   попадёт кто-то, кому снятие не положено, понадобится решение владельца.
4. Смены пароля самим человеком нет: команда умеет завести и отключить.
   Забытый пароль сегодня чинится новой учёткой.
