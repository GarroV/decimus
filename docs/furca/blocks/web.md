# Блок: web

## Назначение

Веб-админка управляющей компании: то, что сегодня доступно только через бота и
MCP, получает экран. Объём спринта — **базовая часть веб-версии** (D133), а не
вся она: каркас с честными заглушками (D138) и раздел «Проверки».

Раскладка берётся из прототипа владельца (`Бриф системы аудитов Decimus 2/
Dodo Audit Prototype v2.dc.html`, 9 разделов навигации), стиль — из
дизайн-системы линейки `GarroV/forma` (`dodo/core/dodo-ds.css` +
`dodo/decimus/domain.css`). Палитра `#5B57F2` и пара Space Grotesk / Manrope из
прототипа в продукт **не переносятся** (D136). Копия `dodo-ds.css` в папке
эталона разошлась с каноном — сверять с `forma`.

## API-контракт

Блок **ничего не считает сам**. Оценка, буква, разбивка по зонам, сроки —
только через уже существующие двери:

| Что нужно экрану | Чем берётся | Запрет |
|---|---|---|
| История проверок, карточка проверки | `src/db/queries.py` | свой SQL поверх тех же таблиц |
| Снятие проверки | `src/db/retract.py` (D086/D089) | второе понятие «удаление» |
| Состав методики, зоны, классы | `src/domain` | чтение `data/*.csv` напрямую |
| Правка методики (позже, T320) | те же двери, что MCP/CLI (D049, D050) | вторая копия правил версионирования |

Веб — **читатель**, а не второй владелец правды. Схему данных этот блок в
первой волне не меняет.

### Признак «построен / не построен»

Единственный источник — **данные** (реестр разделов в коде блока), а не
разметка на каждом экране: иначе он разойдётся с фактом молча (D138). Раздел с
признаком «не построен» получает ленту в навигации и явный экран «ещё в
разработке» при входе, а не пустую или декоративную страницу.

В объём **не входят и показываются непостроенными** (D139): «Календарь»,
«Назначить проверку», планирование как сущность.

## Зависимости

`db` (история проверок, снятие), `domain` (методика, зоны), `mcp` (границы
арендатора и прав — переиспользовать, не дублировать).

## Рамка стека

Задаётся диспетчером, конкретный фреймворк выбирает блок с обоснованием и
записывает в отчёт (D148):

- Python, тот же образ и `docker-compose.yml`, что у бота и MCP;
- **серверный рендеринг**, без сборщика и без Node в образе: дизайн приходит
  готовым CSS из `forma`, а не React-компонентами;
- синхронный код — как весь остальной продукт (`psycopg`, `openai`);
- статика дизайн-системы кладётся копией с указанием версии-источника, чтобы
  расхождение с `forma` было видно.

## Definition of Done блока

- [x] Раздел «Проверки» открывается в браузере и показывает проведённые
      проверки: список, карточка, снятие — на данных, а не на заглушках.
- [x] Все 9 разделов прототипа есть в навигации; непостроенные помечены лентой
      и дают экран «ещё в разработке» (D138).
- [x] Ни один процент и ни одна буква не посчитаны в этом блоке заново.
- [x] Язык интерфейса — параметр, а не константа (требование `CLAUDE.md`);
      тексты заведены на обоих языках (`product-i18n`).
- [x] Проверено живым запуском в браузере, а не только тестами.
- [~] Гейты проекта: формат, линт, типы, мёртвый код, границы модулей — зелёные.
      Полный `make check` в этой копии неполон: строк подключения к базе в ней
      нет намеренно, и тесты блоков `db`/`mcp` пропускаются. Гонит его
      диспетчер на приёмке. Новый пакет `src/web` внесён в контракты
      `import-linter` слоем над `db`/`domain`.
- [x] `docs/` пополнены: `docs/12-web-admin.md`, ссылка в `README.md`,
      переменные — в образце окружения.
- [x] **Вход (T323):** ни один маршрут админки не открывается без опознания;
      выход прекращает сессию на стороне сервера; учётки заводит команда
      проекта; тексты входа на ru и en; границы арендатора не ослаблены.
- [x] **Ограничитель перебора (T325):** после серии неудач форма перестаёт
      принимать пароли, и запертому не помогает верный; счёт переживает
      перезапуск; тексты запрета на ru и en.

## Состояние блока

**Где стоим.** T318 (каркас), T319 («Проверки»), T323 (вход) и T325
(ограничитель перебора) сделаны и проверены стендом. Стек в рамке D148: Flask +
Jinja + waitress, без Node.

**Как устроен вход** (T323, T325, D155; описание — `docs/12-web-admin.md`,
здесь только то, обо что спотыкаются). Заслон — один `before_request`: новый
экран закрыт с минуты появления, открыты два endpoint'а из
`auth.OPEN_ENDPOINTS`. Сессия живёт в базе, а не только в подписанной куке:
иначе выход не прекращал бы доступ по снятой копии. Перебор упирается в счётчик
неудач по адресу и логину (`src/db/web_throttle.py`, миграция `0015`) —
запертая попытка не доходит до сверки пароля вовсе, и верный пароль её не
открывает; счётчик в базе, а не в памяти процесса, потому что перезапуск
случается сам. Права узкие: на `web_users` только `select`, на счётчике
правятся две колонки из пяти.

**Чем проверено.** Блок и соседи по базе — 207 проверок (`-k 'web or migrat'`),
0 упали, 0 пропущены; полный `make test` — 3121 прошли, 0 упали. Зелёным в этой
копии он не станет: нет `examples/`, 22 проверки пропущены, а планка считает
пропуск падением — гейт целиком берёт диспетчер там, где данные есть. Порчей по
T325 — 7 проверок, каждая покраснела с внятной причиной (`make test-honest
ARGS=<тест>`). Стенд: своя база, схема накачена НА ПУСТУЮ (15 миграций).
Браузером: пять неверных паролей → запрет со сроком, верный пароль в это время
не пускает.

**Что дальше.** T324 — не здесь. Публикующему знать обязательно: за туннелем
задаётся `WEB_TRUSTED_PROXIES=1`, иначе все приходят с одного адреса и счётчик
по адресу становится общим на всех (по логину — работает). Новая миграция
вписывается в `tests/test_db_migrations_frozen.py`, а каждый её `grant` — в
`tests/test_db_migrate_roles.py`. Следующий раздел снимает свою ленту в
`src/web/sections.py`.
