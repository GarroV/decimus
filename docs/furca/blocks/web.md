# Блок: web

## Назначение

Веб-админка управляющей компании: то, что доступно через бота и MCP, получает
экран. Объём — **базовая часть веб-версии** (D133): каркас с честными
заглушками (D138) и раздел «Проверки».

Раскладка — из прототипа владельца (`Dodo Audit Prototype v2.dc.html`, 9
разделов), стиль — из `GarroV/forma` (`dodo/core/dodo-ds.css` +
`dodo/decimus/domain.css`); палитра `#5B57F2` и пара Space Grotesk / Manrope в
продукт **не переносятся** (D136). Копия `dodo-ds.css` у эталона разошлась с
каноном — сверять с `forma`.

## API-контракт

Блок **ничего не считает сам**. Оценка, буква, разбивка по зонам, сроки —
только через уже существующие двери:

| Что нужно экрану | Чем берётся | Запрет |
|---|---|---|
| История проверок, карточка проверки | `src/db/queries.py` | свой SQL поверх тех же таблиц |
| Снятие проверки | `src/db/retract.py` (D086/D089) | второе понятие «удаление» |
| Состав методики, зоны, классы | `src/domain` | чтение `data/*.csv` напрямую |
| Правка методики (позже, T320) | те же двери, что MCP/CLI (D049, D050) | вторая копия правил версионирования |

Веб — **читатель**, а не второй владелец правды.

### Признак «построен / не построен»

Единственный источник — **данные** (реестр разделов в коде блока), а не разметка
на экране: иначе он разойдётся с фактом молча (D138). Непостроенный раздел
получает ленту в навигации и экран «ещё в разработке». Не входят в объём и
показаны непостроенными (D139): «Календарь», «Назначить проверку», планирование
как сущность.

## Зависимости

`db` (история, снятие), `domain` (методика, зоны), `mcp` (границы арендатора —
переиспользовать, не дублировать).

## Рамка стека

Рамка диспетчера (D148), выбор блока сделан: **Flask + Jinja + waitress**.
Python, тот же образ и `docker-compose.yml`, что у бота и MCP; серверный
рендеринг без сборщика и без Node — дизайн приходит готовым CSS из `forma`;
синхронный код, как весь остальной продукт; статика дизайн-системы лежит копией
с указанием версии-источника, чтобы расхождение с `forma` было видно.

## Definition of Done блока

- [x] Раздел «Проверки» открывается в браузере и показывает проведённые
      проверки: список, карточка, снятие — на данных, а не на заглушках.
- [x] Все 9 разделов прототипа есть в навигации; непостроенные помечены лентой
      и дают экран «ещё в разработке» (D138).
- [x] Ни один процент и ни одна буква не посчитаны в этом блоке заново.
- [x] Язык интерфейса — параметр, а не константа (требование `CLAUDE.md`);
      тексты заведены на обоих языках (`product-i18n`).
- [x] Проверено живым запуском в браузере, а не только тестами.
- [~] Гейты проекта: формат, линт, типы, мёртвый код, границы модулей — зелёные.
      Полный `make check` в этой копии неполон: строк подключения к базе в ней
      нет намеренно, и тесты блоков `db`/`mcp` пропускаются. Гонит его
      диспетчер на приёмке. Новый пакет `src/web` внесён в контракты
      `import-linter` слоем над `db`/`domain`.
- [x] `docs/` пополнены: `docs/12-web-admin.md`, ссылка в `README.md`,
      переменные — в образце окружения.
- [x] **Вход (T323):** ни один маршрут админки не открывается без опознания;
      выход прекращает сессию на стороне сервера; учётки заводит команда
      проекта; тексты входа на ru и en; границы арендатора не ослаблены.
- [x] **Ограничитель перебора (T325):** после серии неудач форма перестаёт
      принимать пароли, и запертому не помогает верный; счёт переживает
      перезапуск; тексты запрета на ru и en.
- [~] **Конструктор чек-листов (T320):** состав правится с экрана той же
      дверью, что из разговора с агентом; версия на каждую правку, публикация
      отдельным шагом; второй копии правил версионирования не заведено.
- [x] **Снятие запрета (T328, D158):** запертого выпускает команда под ролью
      администратора истории; порог держит и при одновременных попытках; один
      адрес в разных записях — один счётчик. **Якорь на значения (T327):**
      боевые пороги и сроки краснеют, если ограничитель снят настройкой.

## Состояние блока

**Где стоим.** T318, T319, T323, T325, T328, T327 сданы. T320: раздел
«Методика» построен, состав правится дверью хранилища версий, публикация —
отдельной кнопкой; доки, CHANGELOG и живой смоук сделаны. Осталось: свести
наборы исполнителя и прогнать полный набор.

**Как устроен вход** — целиком в `docs/12-web-admin.md`; здесь то, обо что
спотыкаются. Заслон — один `before_request`, открыты два endpoint'а из
`auth.OPEN_ENDPOINTS`. Сессия живёт в базе: иначе выход не прекращал бы доступ
по снятой копии. Заявка и запись попытки — ОДНА операция под замком
(`admit_attempt`), сверка пароля — СНАРУЖИ замка.

**Как устроена правка методики (T320).** Своих правил версионирования в блоке
нет: `src/web/methodology.py` зовёт хранилище версий (`src/mcp/checklist*`),
которым правит и агент по MCP (D049, D050). Хранилище одно на продукт —
`MCP_CHECKLIST_STORE` и `AUDIT_DATA_DIR`, своей переменной у веба нет
намеренно. Правка подписывается в журнале как `web:<логин>`. Экран по умолчанию
показывает СВЕЖУЮ ЗАПИСАННУЮ версию: от неё отсчитывается следующая правка.

**Найдено порчей, чинится не здесь:** разделитель `:` в контракте ярусов
import-linter означает «импортировать МОЖНО», а комментарий рядом обещал запрет
между bot, mcp и web (запрет даёт `|`, и смена трогает все три блока). Свою
половину веб закрывает `tests/test_web_bounds.py`. Честная починка —
переселить хранилище версий ярусом ниже обоих потребителей.

**Что дальше.** T324 — не здесь. Публикующему: за туннелем задаётся
`WEB_TRUSTED_PROXIES=1`, иначе счётчик по адресу общий на всех. Следующий
раздел снимает ленту в `src/web/sections.py`.
