# Управление важными контрольными точками

Complexity: hard

Задача GarroV/backlog#2406. Настройка в редакторе методики: важная точка и
уточнения внутри пункта; зоны, применимость по странам, обязательность ответа
и требование фотографии. Точки идут в существующий раздел контроля.

Основа — технический контроль core (fb2214dd). Данные technical_checks.json
входят в DATA_FILES, отпечаток и снимок издания. Схема и runtime находятся в
src/domain/technical.py. История хранит закреплённые данные и объединяет старые
идентификаторы. Не создавать вторую модель данных.

Изменения выполняются существующим хранилищем версий через apply_edit; публикация
остаётся отдельным действием. Идущие и завершённые проверки сохраняют прежнее
издание. Нужна проверка версии формы, чтобы устаревшая страница не затёрла новую
правку. Одновременные изменения должны сериализоваться средствами хранилища.

Идентификатор точки неизменяемый. Для снятия пометки предпочтительно хранить
enabled=false, чтобы повторное включение сохраняло тот же идентификатор.
Доменные потребители используют только включённые точки; редактор видит и
выключенные. Валидация параметров остаётся общей для импорта и редактора.

UI использует существующую панель пункта методики, отдельные формы без вложенных
form. RU/EN. Формы не показываются для чужого пространства и роли только чтения;
сервер проверяет те же границы через store_for/write и guard checklist.edit.
Не импортировать src.mcp из нового web-модуля: мост только methodology.py.

Приёмка: новая версия после изменения; старый идущий обход не меняется; новая
точка в контроле и отказ завершения без ответа; снятие и повторное включение
с тем же id; архивная история сохраняется; чужой tenant/роль не изменяет файлы;
устаревшая форма получает отказ. Только целевые проверки, без полного набора.
