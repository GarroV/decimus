# API чтения `/api/v1`

> Дока ведётся руками. Задача — #567, модель доступа — #568, решение владельца — D336 (`docs/furca/decisions.md`). Репозиторий публичный: адресов стендов, значений токенов и имён секретов потребителя с их значениями здесь нет намеренно.

## Что это

Decimus — единственный источник данных о проверках и рейтингах РС/РКО. Другие продукты их у себя не хранят и не загружают, а забирают отсюда по API только на чтение. Первый потребитель — главная Swarm: виджеты РС, РКО, собираемость, нарушения, «Куда смотреть» и выездные проверки. Запросы идут с сервера Swarm (Supabase Edge Function), не из браузера.

API выключен по умолчанию и открывается переменной `API_ENABLED=1` (§«Включение»).

## Поверхности

| Маршрут | Право токена | Что отдаёт | Откуда данные |
|---|---|---|---|
| `GET /api/v1/ratings/scores` | `ratings:read` | баллы пиццерий по периодам рейтинга | `ratings.scores` (`src/db/ratings_read.py: score_facts`) |
| `GET /api/v1/ratings/checkups` | `ratings:read` | собираемость: проверки пиццерии за период по каналам | `ratings.checkups` (`checkup_counts`) |
| `GET /api/v1/ratings/violations` | `ratings:read` | топ нарушений по стране за период | `ratings.violations` (`period_violations`) + `summary.violation_block` |
| `GET /api/v1/inspections` | `inspections:read` | выездные проверки Decimus: пиццерия, дата, итог | `inspections` (`src/db/api_inspections.py`) |
| `make api-token` | — | выпуск, список и отзыв токенов | `api_tokens` (миграция `0041`) |

Всё прочее под `/api/v1` отвечает `404 not_found` — но только предъявившему живой токен; без токена — `401`.

Код: маршруты и заслон — `src/web/api.py`, лимит частоты — `src/web/api_limits.py`, формы ответов рейтингов — `src/ratings/api_payload.py`, токены — `src/db/api_tokens.py`.

## Сквозной сценарий

Команда выпускает Swarm токен с нужными правами (`make api-token`), кладёт значение в секреты Swarm и включает `API_ENABLED=1` на стенде. Swarm на своём сервере зовёт маршруты с заголовком `Authorization: Bearer <токен>`, кэширует ответ 5 минут и сам отбирает страны под рынки воркспейса. Контроль загружает выгрузки рейтингов как обычно (`docs/15-ratings.md`) — следующий запрос Swarm видит новые данные. Ротация: выпустить новый токен, заменить секрет у Swarm, отозвать старый; перезапуск не нужен.

## Словарь

- **Потребитель** — сервис, которому выпущен токен (`swarm`).
- **Право (scope)** — что открывает токен: `ratings:read` — три маршрута рейтингов, `inspections:read` — проверки. Список допустимых держит схема (CHECK в `0041`).
- **Отпечаток** — SHA-256 токена; в базе лежит только он.

## Общие правила контракта

- Заголовок `Authorization: Bearer <токен>`. Кука админки к API доступа не даёт, токен не открывает ни одного экрана админки.
- `countries=RS,HR,…` — коды ISO-2 стран охвата IMF (справочник `src/ratings/countries.py`, без RU, KZ, UZ). Без параметра: для рейтингов — страны IMF из справочника рейтингов (`ratings.countries`), для проверок — все страны IMF.
- `from`, `to` — `YYYY-MM-DD`, включительно. Период рейтинга попадает в выборку по дню начала, как в сводке. Без дат — вся история.
- Периоды в ответе — по возрастанию; массивы `scores`, `counts`, `top` выровнены по `periods`.
- Ответ — JSON. Ошибка — `{"error": "<код>", "message": "<текст>"}` с кодом 4xx/5xx; тексты на английском, опираться надо на код.
- Неизвестный параметр — `400 unknown_parameter` (опечатка `country=` не превращается в «все страны»); повтор параметра — `400 bad_parameter`.
- Удачный ответ — `Cache-Control: private, max-age=300`, `Vary: Authorization`; ошибки — `no-store`. `private` не даёт общим кэшам по дороге сохранить ответ на запрос с токеном.

### `GET /api/v1/ratings/scores?type=rs|rko&countries=&from=&to=`

```json
{ "type": "rs",
  "periods": [{ "id": 12, "start": "2026-09-16", "end": "2026-09-30",
                "title_ru": "Сентябрь 2 часть 2026", "title_en": "September part 2 2026" }],
  "units": [{ "id": "<dodo_id 32 hex>", "name": "Belgrade-1", "cc": "RS", "developer": "…",
              "scores": [96.5] }],
  "loaded_at": "2026-10-08T19:40:00Z" }
```

`scores[i]` — балл за `periods[i]`, `null` — оценки нет. В `units` только пиццерии, у которых есть хоть один балл в выбранных периодах. `developer` — девелопер страны из справочника «страна → девелопер» (`null`, если не назначен). `loaded_at` — время последней удачной загрузки любого формата (`null`, если загрузок не было).

### `GET /api/v1/ratings/checkups?type=rs|rko&countries=&from=&to=`

```json
{ "type": "rko", "periods": [ … ],
  "units": [{ "id": "<dodo_id>", "cc": "RS",
              "counts": [{ "restaurant": 2, "delivery": 3, "inspection": 0, "online": 0 }, null] }] }
```

Проверка попадает в период, если её дата (UTC) внутри дат периода; отклонённые на приёмке фото-проверки РКО не считаются — то же правило, что у сводки. `null` — у пиццерии в периоде нет ни одной проверки.

### `GET /api/v1/ratings/violations?type=rs|rko&countries=&from=&to=&top=5`

```json
{ "type": "rs", "periods": [ … ],
  "countries": [{ "cc": "RS", "top": [[{ "text": "Грязный пол", "criterion_id": "17", "count": 3 }], []] }] }
```

`top` — от 1 до 20, по умолчанию 5. Топ считается функцией сводки (`summary.violation_block`): тексты схлопываются без пометки (ML)/(ИИ)/(AI) и без учёта регистра; РС — замечания периода из снимка, РКО — «Выявленные нарушения» проверок периода (не «Другие проблемы»). `criterion_id` — код критерия из данных, самый частый среди схлопнутых строк; у нарушений РКО из CSV кода нет — `null`. Пустой список — в периоде нарушений нет или нет данных (контракт их не различает).

### `GET /api/v1/inspections?countries=&from=&to=`

```json
{ "inspections": [{ "id": "<uuid>",
                    "unit": { "id": "<uuid>", "dodo_id": "<32 hex|null>", "name": "Belgrade-1", "cc": "RS" },
                    "date": "2026-10-02", "status": "finalized", "score_pct": 97.5, "grade": "A",
                    "url": "https://<адрес админки>/inspections/<uuid>" }] }
```

Только проверки истории: принятые на приёмке (`status = finalized`, D199) и не отклонённые. Ждущие приёмки не отдаются — их оценку ещё правят. `score_pct` и `grade` — то, что записал движок (`engine/audit.py score`) при сливе; API ничего не пересчитывает. `unit.dodo_id` — id пиццерии в Dodo IS, если пиццерия сопоставлена в справочнике рейтингов, иначе `null`. `url` — карточка проверки в админке (открывается после входа). Новые первыми.

## Коды ответа

| Код | `error` | Когда |
|---|---|---|
| 400 | `bad_type`, `bad_countries`, `bad_date`, `bad_range`, `bad_top`, `unknown_parameter`, `bad_parameter` | параметр не прошёл проверку |
| 400 | `range_too_large` | больше 156 периодов рейтинга или 5000 проверок в ответе — сузить `from`/`to` |
| 401 | `unauthorized` | нет заголовка, токен не похож на выпущенный, незнакомый или отозванный — ответ один и тот же |
| 403 | `forbidden` | у токена нет права на этот маршрут |
| 404 | `not_found` | маршрута нет (только с живым токеном) |
| 429 | `rate_limited` | превышен лимит; `Retry-After` — через сколько секунд |
| 503 | `unavailable` | база недоступна; подробностей наружу нет |
| 500 | `internal` | сбой обработки; трассировка — только в журнале сервера |

## Токены

```bash
make api-token ARGS="issue swarm --scope ratings:read --scope inspections:read --by <кто>"
make api-token ARGS="list"
make api-token ARGS="revoke <id> --by <кто>"
```

- Выпуск печатает значение **один раз** (`dcm_` + 43 знака). В базе только отпечаток SHA-256; колонка физически не примет сырой токен (CHECK на 64 hex). Потерянный токен не восстанавливается — выпускается новый.
- Выпускает и отзывает роль повышенных полномочий — та же, что заводит учётки админки (`DATABASE_RETRACTION_URL`, без неё `DATABASE_ADMIN_URL`). Роль приложения только сверяет токен и отмечает время последнего использования: выпустить, отозвать, поменять права или отпечаток она не может (колоночные права `0041`).
- Отзыв — пометка «кто и когда», строка остаётся следом и не воскрешается (сужающая политика). Действует со следующего запроса: токен сверяется с базой на каждом обращении.
- `list` показывает id, потребителя, права, кто выпустил и отозвал, время последнего вызова — без значений и отпечатков.
- Приставка `dcm_` нужна сканерам секретов: токен, случайно попавший в код или журнал, узнаётся по ней.

## Лимиты

- 60 запросов в минуту на токен (`api_limits.PER_TOKEN_PER_MINUTE`): Swarm кэширует ответы на 5 минут, запас — на прогрев всех виджетов.
- 20 неудачных предъявлений в минуту с адреса (`FAILURES_PER_MINUTE`): после них адрес получает 429, даже с верным токеном, до конца окна. Подбирать токен бесполезно (256 бит), но каждая попытка стоит похода в базу.
- Счётчик — скользящее окно в памяти процесса админки. Админка работает одним процессом, поэтому он видит все запросы; перезапуск обнуляет счётчик. Станет процессов несколько — счётчик придётся вынести в базу.
- Адрес берётся так же, как у ограничителя входа: `WEB_TRUSTED_PROXIES` (на проде 1 — Caddy).

## Журнал обращений

Каждое обращение к `/api/v1` пишет в журнал приложения (логгер `src.web.api`, уровень INFO) одну строку JSON:

```json
{"event":"api_access","consumer":"swarm","token_id":"<uuid>","method":"GET",
 "path":"/api/v1/ratings/scores","params":{"countries":"RS","type":"rs"},
 "status":200,"ms":42,"address":"<адрес вызывающего>"}
```

Токена и заголовка `Authorization` в журнале нет; в `params` только параметры контракта, путь и значения обрезаны до 120 знаков. При 401 `consumer` пуст. Отдельной таблицы журнала нет: «кто и когда последний раз пользовался токеном» отвечает `last_used_at` (пишется не чаще раза в минуту).

## Включение

1. Накатить миграции (`0041_api_tokens.sql`).
2. Выпустить токен потребителю (`make api-token ARGS="issue …"`), значение — сразу в секреты потребителя.
3. `API_ENABLED=1` в `.env` стенда, перезапустить веб-сервис. Без переменной маршрутов API нет вовсе; любое значение, кроме пусто, `0` и `1`, — отказ на старте.
4. Смоук с сервера: без токена `401`, с токеном `200` на один маршрут.

Порядок на проде — `docs/08-deploy.md` §8.16; раскатка — только в окно и по «да» владельца.

## Что не входит в v1

- Запись (загрузка рейтингов через API, `ratings:import`) и перевод MCP-токенов на общую модель — #568.
- Ограничение токена по странам или пространству: Swarm отбирает страны сам (#567). Охват API — вся сеть.
- CORS: вызовы серверные, браузер с чужого адреса API не позовёт.
