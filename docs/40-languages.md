# 40. Языки: где живут, как добавить новый

> Ручной документ. Канон по теме «язык» — здесь; карта кода (`docs/00-map.md`)
> и инвентарь ссылаются сюда, а не повторяют. Правите код из таблиц ниже —
> правьте документ тем же коммитом.

## Что это и зачем

Проверка ведётся на одном языке, а отчёт и письмо партнёру уходят на другом:
аудитор говорит по-русски, партнёр в Сербии читает по-английски. Поэтому язык в
продукте — не одна настройка, а **четыре разных**, и путать их нельзя:

| Язык | Чей | Где выбирается | Где хранится |
|---|---|---|---|
| Интерфейса | человека | веб: меню учётки, «Настройки», вход; бот: `/lang` | профиль учётки (`web_own_profile`), `bot_ui_langs` (0035) |
| Речи аудитора | проверки | бот и мини-апп на старте | `inspections.speech_lang` |
| Чек-листа | человека | мини-апп на старте (D451) | `checklist_langs` (0057) |
| Отчёта | проверки | конец проверки: бот (`src/bot/report_lang.py`), мини-апп (`walk-finish.js`) | `inspections.report_lang` |

Какие языки отчёта предлагать в стране — данные, не код: сначала перекрытие из
вкладки «Администрирование → Страны» (`country_report_langs`, 0098, D640), затем
`report_langs.json` в каталоге методики (`src/domain/report_langs.py`, D415).

## Что переводится чем

| Что | Откуда текст на нужном языке |
|---|---|
| Формулировки методики: процесс, вопрос, зона, подпись оценки, примечание D3 | файлы версии методики: `checklist.csv` (`process_<яз>`, `question_<яз>`), `zones.csv` (`name_<яз>`), `scoring.json` (`label_<яз>`, `d3_note_<яз>`) |
| Постоянные тексты отчёта и письма | каталоги в коде: `engine/report.py` (`T`, `GRADE_NOTE`, `ITEM_REF`, `LETTER_*`, `LETTER_FEEDBACK`), `src/report/batch_letter_texts.py`, `src/report/info_titles.py`, `src/web/google_mail.py` (`SUBJECT_TITLES`), `src/domain/kinds.py` и `engine/audit.py` (`INSPECTION_KINDS` — две копии) |
| Названия городов в письме | `src/domain/geo.py` (`CITIES`) |
| Шаблоны писем, правленные в админке | таблица `mailing_templates` (0104) |
| Свободный текст аудитора (комментарий, ответ) | переводит модель: `src/recognize/translate.py`; в конце проверки — `src/bot/finish_translate.py`, в мини-аппе — `src/web/walk_translate.py` |
| Тексты интерфейса | веб — `src/web/texts*.py`, бот — `src/bot/texts.py`; полноту по языкам держат `tests/test_web_texts.py` и тест бота |

Таблица `translations` (0001) и колонки `lang` в 0019/0057/0098/0128 от числа
языков не зависят.

## Где сейчас зашита пара ru/en

На 10.11.2026 третий язык добавить словарём нельзя: пара `ru`/`en` зашита в код.
Это предмет #541; турецкий (D743, #1619) идёт через снятие этих мест.

* **Один список на всё.** `TEXT_LANGS = ("ru", "en")` в `src/domain/models.py` —
  одновременно «на каком языке есть методика» и «на каком говорит аудитор»
  (через `LANG_LABELS` в `src/bot/keyboards.py` его видят бот и мини-апп).
  `pick_text(ru, en, lang)` там же выбирает из двух аргументов.
* **Движок.** `engine/audit.py`: `LANGS`, `clean_lang`, ключи `question_/process_/
  zone_name_/grade_label_` только с `_ru`/`_en`. `engine/report.py`: выбор полей
  `"…_en" if lang == "en" else "…_ru"`, единицы «ч/мин», имя файла «Аудит».
* **Чтение методики.** `engine/manage.py` (`FIELDS`, `ZONE_FIELDS`) — неизвестные
  колонки сохраняет, но движок их не читает. Инструменты MCP правки чек-листа
  (`src/mcp/checklist_tools.py`) принимают только `*_ru`/`*_en`.
* **База.** `mailing_templates.lang` с проверкой `in ('ru','en')` (0104);
  подпись оценки пишется в `translations` только на два языка (`src/db/push.py`);
  рейтинги (0039) и план действий (0092, `src/report/plan_terms.py`) — колонки
  `name_ru/name_en`.
* **Веб.** `LETTER_LANGS = TEXT_LANGS` (`src/web/inspections.py`), `in ('ru','en')`
  в `templates/inspections/card.html`, `_pick` в `src/domain/item_label.py`,
  `methodology_view.py`, `unit_card.py`, `mailings_screen.py`.

## Выгрузка готовой проверки на другом языке

* **Письмо** — можно: выпадающий список языка в `_letter_form.html` (одиночное) и
  `country/_batch.html` (общее, D739); язык проверяется по `TEXT_LANGS`, по
  умолчанию — `report_lang` проверки (`src/report/letters.py`, `src/report/batch_letter.py`).
* **PDF** — нельзя: `/…/<id>/report` печатает на `report_lang`, хранится один PDF
  на проверку (`inspection_reports`, 0018, без `lang`), пересборка — только при
  смене содержимого (`src/report/current_pdf.py`).
* **Свободный текст.** `finish_translate.py` переводит комментарий на язык отчёта
  и **затирает** исходник — второй перевод делается уже с перевода.
* **Исторические проверки** (`origin = 'legacy'`, D332) не пересобираются ни на
  каком языке: их отчёт перенесён как есть (`docs/14-history-import.md`, D743).

## Как добавить язык

Пока #541 не закрыт, порядок такой — после него документ сокращается до
«строка в списке + словари»:

1. Снять пару ru/en из мест раздела «Где сейчас зашита пара ru/en».
2. Завести язык в списке языков отчёта; язык интерфейса и речи — отдельно, только
   если он там нужен.
3. Перевести постоянные тексты (раздел «Что переводится чем») — тест полноты
   должен падать на пропущенном ключе.
4. Добавить колонки `*_<яз>` во все версии методики, по которым будут
   выгружать проверки, и в `engine/manage.py`.
5. Проверить эталоны: `examples/belgrade-1` — 97.5%, A; `belgrade-2` — 97.0%, A.
