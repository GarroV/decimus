# Связь РС/РКО и собственных проверок — предложение по пункту 18

Статус: предложение для владельца; поведение платформы не изменено.

## Что уже есть

«Качество» сопоставляет показатели пиццерии за месяц. РС/РКО читаются по
`ratings.units.dodo_id`, собственная принятая проверка — по `units.code`;
`src/db/quality_read.py` возвращает исходный записанный процент без пересчёта.
В рейтингах есть замечания с внешним `criterion_id` и `parent_name`, но внешнее
поле необязательно (`src/ratings/model.py: Violation`). В наших находках используются
коды собственной версии методики и физическая зона.

Следовательно, можно достоверно сопоставить пиццерию и период. Автоматически
считать два замечания одним нарушением по сходству текста или названию зоны нельзя:
общего обязательного идентификатора критерия сейчас нет.

## Предлагаемый первый результат

В существующей странице «Качество» у выбранной пиццерии и месяца показать рядом:
исходные РС и РКО с их периодами, последнюю принятую собственную проверку с датой
и ссылками на источники каждого значения. Там же раскрывать замечания каждого
источника отдельными списками. Отсутствующие данные обозначать явно, без нулевого
балла. Сохранять действующий охват пользователя и существующую подсветку РС/РКО
из D677; новых порогов, сводного балла и повторного начисления вычетов не вводить.

Это позволит открыть проблемную пиццерию и сравнить, что находили разные проверки,
не выдавая временное совпадение за доказанную причину падения рейтинга.

## Если нужна подсветка именно совпадающих проблем

Нужна подтверждаемая таблица соответствий: тип внешнего источника + внешний
criterion_id → код и версия нашей методики. Сопоставление по словам допустимо
только как предложение человеку. Замечания без внешнего id остаются несвязанными.
Ручное подтверждение связи хранит автора и источник; изменение текстов и оценок
исходных проверок для связи не требуется.

До подтверждения владельцем такого результата и правил соответствия отдельный
автоматический классификатор или новая система рейтинга не строится. Пункт 18
имеет подготовленное предложение, но не считается реализованной функцией.
