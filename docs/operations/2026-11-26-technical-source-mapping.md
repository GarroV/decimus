# Технический осмотр: сопоставление исходного документа

Дата разбора: 26.11.2026. Расширение подготовлено для согласования на стенде.
Исходный DOCX, переводы, полная таблица сопоставления и издание методики хранятся
вне публичного репозитория. В этом документе — только структура и связи по кодам.

Основа итогового издания — `base-current`: копия действующей методики, полученная
только для чтения и сверенная с рабочей системой 26.11.2026. Сохранены актуальные
`scoring.json`, `photo-cues.md` и дополнительная колонка `letter_role`:
`INF01=strengths`, `INF06=growth`. У старой локальной копии этой колонки не было.
Различие `scoring.json` со старой копией затрагивало только пояснение
`_repeat_comment`, ставки совпадали. В итоговом издании файл скопирован побайтно.

В документе 73 нумерованные строки и одна самостоятельная ненумерованная строка
после №18. Она получила ссылку `18.1` и код `TC018E`. Итого 74 контрольные точки;
По решению владельца все 74 контрольные точки требуют явного ответа. Исходный
признак «обязательный / дополнительный» сохраняется в `source_required` как
происхождение данных и не снимает обязательность ответа. Если объекта нет,
проверяющий явно указывает неприменимость и её причину. Страновая применимость
MD/EE/ME сохраняется. Один контроль, применимый в нескольких физических зонах, требует отдельного
ответа в каждой применимой зоне. Наличие объекта и применимость подтверждает
проверяющий; отсутствие оборудования не означает автоматически исправное состояние.

## Что изменяет импорт

`tools/technical_import.py` создаёт отдельный каталог издания. Исходный каталог
и уже существующий выходной каталог не перезаписываются. Без `--apply` запись
не выполняется. Изменяются только:

- `technical_checks.json`: контрольные точки, тексты RU/EN, связь с исходными
  строками, применимость и отпечаток источника;
- `criteria.md`: уточнения осмотра в 44 существующих разделах;
- `checklist.csv`: применимость существующих пунктов в дополнительных зонах;
- `checklist_version.txt`: имя нового издания;
- `technical_import_provenance.json`: отпечатки исходных файлов и решения по
  расхождениям. Этот файл также остаётся вне репозитория.

Все 136 пунктов и десять физических зон сохранены. Новых штрафных пунктов нет.
Уровни, сроки и `scoring.json` не меняются. Порядок `route.csv` сохраняется:
новых пунктов, требующих изменения существующего маршрута, не добавлено.

## Воспроизводимое применение

`SOURCE_DOCX`, `SOURCE_METHOD`, `SOURCE_MAPPING` и `NEW_METHOD` указывают на файлы
и каталоги вне репозитория. Таблица сопоставления содержит английские переводы,
связи по кодам и решения о применимости. Её отпечаток источника должен совпасть
с DOCX. Изменившийся документ требует повторной сверки таблицы.

```sh
python tools/technical_import.py \
  --source "$SOURCE_DOCX" --base "$SOURCE_METHOD" \
  --mapping "$SOURCE_MAPPING" --output "$NEW_METHOD" \
  --edition 'imf-technical 2026-11-26'

# Тот же вызов с --apply создаёт новый каталог издания.
CHECKLIST_DIR="$NEW_METHOD" python engine/manage.py validate
```

Без полной таблицы соответствия, перевода или известной зоны импорт отказывает
до записи. DOCX читается с ограничением размера и защищённым XML-парсером,
который уже входит в зависимости проекта.
