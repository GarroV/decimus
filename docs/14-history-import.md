# Загрузка проверок задним числом через Claude

Как перенести в историю сети проверки, которых нет в боте: старые отчёты (PDF
Qvalon, Битрикс, таблицы, свободный текст) и недавние проверки, заведённые после
факта (D305–D310, D332–D335). Загрузка поштучная: одна проверка — один разговор
с Claude, вы смотрите каждую запись и подтверждаете проверку сами.

Кому: только управляющей компании (D335). Партнёрам загрузка задним числом не
открывается никакой настройкой.

Статус: на ветке `feat/import-modes`, 09.10.2026. На прод не раскатывалось
(порядок включения — `docs/08-deploy.md` §8.15).

## Два режима — выбираются один раз

Режим называют при создании черновика (`mode`), и потом он не меняется. Смешать
режимы в одной проверке нельзя (D334).

| | `history` — историческая | `current` — текущая |
|---|---|---|
| Когда | Старый отчёт по **прежней** методике: Qvalon со «Score 95.29, Status, Issues», старые чек-листы на 253/217/150 вопросов, Битрикс, таблицы | **Недавняя** проверка по **нынешнему** чек-листу, заведённая после факта (например, две недели назад) |
| Оценка | Переносится **как в отчёте** и не пересчитывается никогда — ни сейчас, ни при следующей смене методики (D332) | Считает движок по действующей версии, как у проверки из бота |
| Обязательно при создании | точка, дата визита, оценка из отчёта (`reported_pct`) | точка, дата визита, аудитор |
| По желанию | буква (если в отчёте была), статус из отчёта словами («Passed», «Not passed», «Issues (D2)»…), метка старой методики («Qvalon 133», «старый чек-лист 253»), аудитор, ссылка на источник | оценка и буква из отчёта — только для сверки с посчитанной |
| Чек-лист и версия | Не выбираются: проверка встаёт в линию эталона УК, прежняя методика называется меткой | Только действующая версия эталона УК; старую выбрать нельзя — отказ словами |
| Записи | Описание отчёта: формулировка обязательна; код пункта, класс (D1/D2/D3) и зона — если отчёт их называет | Как в боте: код, класс, зона обязательны, каждую запись сверяет движок |

Не уверены, какой режим, — режим `history`, если проверка шла не по нынешнему
чек-листу. Подгонять записи под оценку отчёта не нужно и нельзя: оценка
исторической — это оценка отчёта.

## Что получится

После подтверждения проверка — в истории точки, в реестре и в сводках рядом с
проверками из бота (D306).

- **Историческая** показывает оценку, букву и статус ровно как в старом отчёте,
  с пометкой «историческая проверка, оценка по методике того времени» и меткой
  методики. Разбивки по зонам и вычетов у неё нет. Запись без класса
  показывается «без класса», без пункта — «пункт не назван». Каждая прежняя
  методика в сводке сопоставимости — отдельная группа.
- **Текущая** — обычная проверка действующей версии: оценка, разбивка по зонам,
  вычеты, как у обхода.
- **Ни по одной** не открывается запрос экшн-плана, письма партнёру по ним нет,
  и никому ничего не отправляется (D310).
- Фото не обязательны (D309). Прикладывают только снимки, относящиеся к
  нарушениям (D333).

## Что нужно заранее

1. **Доступ.** Личный токен MCP (выдаёт бот) и включённая загрузка
   (`MCP_IMPORT_TENANTS=HQ`). Без неё Claude получит отказ доступа.
2. **Точка в справочнике.** Загрузка точек не заводит: опечатка в названии
   разделила бы историю одной пиццерии на две. Нет точки — сначала её заводят в
   справочнике.

## Порядок работы

1. **Начать.** Дайте Claude отчёт и скажите, старый это отчёт (`history`) или
   недавняя проверка по нынешнему чек-листу (`current`). Claude заводит
   черновик (`import_create_inspection`) — для исторической с оценкой, буквой и
   статусом из отчёта.
2. **Внести записи** (`import_add_finding`) — по одной на нарушение отчёта.
   - Историческая: формулировка как в отчёте; код, класс и зону — только если
     они в отчёте есть. Незнакомый нынешнему чек-листу код принимается с
     предупреждением — проверьте, не опечатка ли. Оценка от записей не меняется.
   - Текущая: каждую запись проверяет движок, как в боте (пункт есть, класс
     допустим, зона есть, одна пара «пункт + зона» — одна запись). Отказ движка
     приходит словами, и ничего не записывается.
3. **Поправить, если нужно.** Исправить запись (`import_edit_finding`) или
   убрать (`import_remove_finding`) — по её номеру. Фото — `import_add_photo`.
4. **Сверить** (`import_get_inspection`).
   - Историческая: оценка, буква и статус совпадают с отчётом слово в слово.
   - Текущая: посчитанная оценка рядом с оценкой из отчёта, если вы её
     называли. Расходится — обычно пропущена или лишняя запись, не тот класс или
     пропущена пометка повтора.
5. **Подтвердить** (`import_accept_inspection`) с названием точки и датой, как
   они записаны в черновике. После этого проверка в истории и больше не
   правится. Ошибочную подтверждённую снимают снятием из истории.
6. **Или удалить.** Начали не ту точку или дату — `import_discard_draft`
   удаляет черновик целиком вместе с записями и фото. Проверок из бота и уже
   подтверждённых он не касается.

Незаконченные черновики обоих режимов видны в `import_list_drafts`.

## Пределы

| Что | Предел |
|---|---|
| Фото | JPEG, PNG или WebP, до 700 КБ; больше — уменьшить перед отправкой |
| Фото у одной записи / у черновика | 10 / 300 |
| Записей в черновике | 300 |
| Неподтверждённых черновиков в пространстве | 200 |
| Формулировка и комментарий | 1000 знаков |
| Статус из отчёта / метка методики | 60 / 100 знаков |

## Как устроено внутри (для разработчика)

- Режим — происхождение проверки `inspections.origin`: `import` — текущая,
  `legacy` — историческая (миграция `0042`). Не переписывается (триггер
  `inspections_origin_fixed`).
- Историческая: `pct = reported_pct` (держит и база, ограничение
  `inspections_legacy_score_as_is`), `grade = reported_grade` или пусто,
  `deductions = 0`, `by_zone = {}`, `counts` — счёт записей по классам.
  `checklist_code` — код эталона УК (чтобы проверка шла в одной линии с
  нынешними), `checklist_version` — `legacy:<метка>`, заведомо не версия
  хранилища. Не названное отчётом — маркеры: код `LEGACY`, класс `NC`, зона
  пустая (`src/db/models.py`).
- Движок не трогает историческую ни на одном пути: записи
  (`src/db/imports_legacy.py`), правка на приёмке (`src/db/revise.py`),
  пересчёт (`src/report/rescore.refuse_legacy`), письмо
  (`src/report/letters.refuse_uploaded`).
- Выключатель — `MCP_IMPORT_TENANTS` пустая (`docs/08-deploy.md` §8.15).

## Чего нет

- **Сведений о визите** (информационная часть, INF-пункты) загрузка не
  принимает — только записи.
- **Пакетной загрузки** нет намеренно: каждую проверку смотрит человек.
