# Загрузка исторических проверок через Claude

Как перенести старые проверки (из Битрикса, PDF, таблиц) в историю сети, чтобы
по ним работала аналитика точки (D305–D310). Загрузка поштучная: одна
проверка — один разговор с Claude, вы смотрите каждую запись и подтверждаете
проверку сами.

Статус: на ветке `feat/history-import`, 08.10.2026. На прод не раскатывалось
(порядок включения — `docs/08-deploy.md` §8.15).

## Что получится

После подтверждения загруженная проверка — обычная проверка своей версии
методики. Она в истории точки и в сводках наравне с обходами из бота, её оценку
посчитал движок по ТОЙ версии чек-листа, по которой проверяли тогда.

Отличия от проверки обхода:

- **Запрос экшн-плана не открывается** и никому ничего не отправляется: на
  отчёт прошлых лет партнёру отвечать нечего (D310).
- **Оценка из старого отчёта в аналитику не идёт.** Её вы называете только для
  сверки: Claude покажет, совпала ли она с посчитанной.
- Фото не обязательны (D309). Можно приложить, если они есть в источнике.

## Что нужно заранее

1. **Доступ.** Личный токен MCP (выдаёт бот) и пространство, которому открыта
   загрузка (`MCP_IMPORT_TENANTS`). Без права Claude получит отказ доступа.
2. **Точка в справочнике.** Загрузка точек не заводит: опечатка в названии
   иначе разделила бы историю одной пиццерии на две. Нет точки — сначала её
   заводят в справочнике.
3. **Старая версия методики.** Если проверка делалась по чек-листу, который с
   тех пор менялся, эта старая версия должна существовать. Её собирают
   инструментами методики: по одной версии на каждое изменение старой
   методики, и проверки того периода грузятся по ней. Список версий —
   `checklist_versions`.

## Порядок работы

1. **Начать.** Дайте Claude старый отчёт и скажите, какой это чек-лист и
   версия. Claude заводит черновик (`import_create_inspection`): точка, дата
   визита, аудитор, версия, оценка из отчёта и ссылка на источник.
2. **Внести записи.** По одной на каждое нарушение, информационную запись или
   рекомендацию отчёта (`import_add_finding`). Каждую проверяет движок, как в
   боте: пункт есть в этой версии, класс для него допустим, зона есть в
   справочнике. Отказ движка приходит словами, и ничего не записывается.
   Несколько предметов одного пункта в одной зоне — ОДНА запись. Повтор
   («повторное нарушение») — только если так сказано в отчёте.
3. **Поправить, если нужно.** Исправить запись (`import_edit_finding`) или
   убрать (`import_remove_finding`) — по её номеру. Фото — `import_add_photo`.
4. **Сверить.** `import_get_inspection` показывает посчитанную оценку, буквы и
   расхождение с оценкой из отчёта. Расходится — обычно пропущена или лишняя
   запись, не тот класс, пропущена пометка повтора или выбрана не та версия.
5. **Подтвердить.** `import_accept_inspection` с названием точки и датой — как
   они записаны в черновике. После этого проверка в истории и больше не
   правится. Ошибочную подтверждённую снимают снятием из истории.
6. **Или удалить.** Начали не ту точку или дату — `import_discard_draft`
   удаляет черновик целиком вместе с записями и фото. Проверок обхода и уже
   подтверждённых он не касается.

Незаконченные черновики видны в `import_list_drafts`.

## Пределы

| Что | Предел |
|---|---|
| Фото | JPEG, PNG или WebP, до 700 КБ; больше — уменьшить перед отправкой |
| Фото у одной записи / у черновика | 10 / 300 |
| Записей в черновике | 300 |
| Неподтверждённых черновиков в пространстве | 200 |
| Формулировка и комментарий | 1000 знаков |

## Чего нет

- **Сведений о визите** (информационная часть, INF-пункты) загрузка не
  принимает — только записи.
- **Пакетной загрузки** нет намеренно: каждую проверку смотрит человек.
